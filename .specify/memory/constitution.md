# Closed-Loop Network Experiment Agent 项目宪法

本项目是一个闭环网络实验 Agent：基于 LangChain ReAct 的自主流量参数探索系统，通过持续后台 ping 监控最大化 RTT，集成 Pktgen-DPDK 硬件发包与 TRex 客户端，并内置严格安全约束（allowlist、速率限制、HITL 审批）。

## 项目原则

### 一、先想清楚再动手（计划先行）

任何功能在写第一行代码之前，必须先完成该功能的规格（spec.md）、实现计划（plan.md）与任务列表（tasks.md），并经一致性检查通过；未经规格与计划的功能，不得直接进入实现。实现过程中不得擅自扩张 tasks.md 之外的目标。

理由：无计划的实现必然返工；规格与计划先行把歧义和风险挡在代码之前。

### 二、闭环驱动（全流程收敛）

每个功能必须走完整 SDD 闭环：specify → plan → tasks → implement → converge，实现完成后必须运行收敛评估，对照规格与宪法检查真实代码，把「缺失 / 部分完成 / 相矛盾」的工作追加为任务并完成，直到收敛才可宣称功能完成。本项目自身的实验闭环（攻击 → RTT 观测 → 参数决策 → 再攻击）同样适用：每个动作必须有观测回馈。

理由：只有收敛的闭环才有价值；半成品、无回馈的动作不计入进展。

### 三、测试伴随（新功能必配测试）

新写的功能必须附带相应的测试：核心逻辑改动前先写测试（红-绿-重构），每个新功能至少配套单元测试；涉及真实编译器/网络的部分配套集成测试。宣称完成前，测试必须实际运行并通过，不得以「代码看起来没问题」代替测试结果。

理由：没有测试的功能无法证明正确，也无法防止回归。

### 四、安全优先（不可协商）

所有流量工具必须执行 allowlist 校验、禁止广播/组播与源 IP 伪造；真实流量发送必须经过 HITL 审批门禁；参数不得超过宪法规定的上限。任何绕过安全门禁的「捷径」一律拒绝。

理由：本项目会产生真实网络流量，误伤或越权发送是不可接受的后果。

### 五、可观测驱动（数据说话）

每个攻击动作必须采集 RTT 观测数据（`rtt_during` / `covers_attack_window`）；优化决策必须基于实测数据而非猜测，无观测回馈的动作不得作为决策依据。

理由：闭环 Agent 的价值在于基于反馈的自主优化，数据缺失时的一切「优化」都是噪声。

### 六、配置单一来源

参数默认值集中于 `src/config/experiment.json`，经环境变量注入工具并在调用时读取；不得在工具函数中硬编码默认值。allowlist 由 `src/config/allowlist.json` 唯一管理。

理由：单一来源避免配置漂移；调用时读取保证 CLI 运行时覆盖生效。

## 附加约束

- **跨平台**：检测 `sys.platform`，不得硬编码 OS 特定标志。
- **参数上限**：pps=20000、duration=20s、packet_size=1024、flow_count=100、Pktgen duration≤60000ms、Pktgen rate≤100%。
- **Vendored 同步**：第三方 vendored 代码（`pktgen_agent/`、`dsl/`、`topology.yaml`）与上游 Lua 项目保持同步，不得私自分叉语义。
- **文档真实性**：工具 docstring 与系统提示中的参数限制必须与实际常量一致（当前已知 docstring 滞后，修订时一并修复）。

## 开发工作流

- **分步触发**：每个 speckit-* 技能一步一触发；每步结束必须汇报产物并提示下一步，不得跨技能自动连续执行。
- **功能顺序**：constitution（一次性）→ specify → [clarify] → plan → [checklist] → tasks → [analyze] → implement → converge。
- **质量门禁**：进入 implement 前 tasks.md 完整；宣称完成前单元/集成测试全部通过。

## 治理

- 宪法高于一切其他实践：所有计划、任务与实现必须对照宪法核对合规性。
- **修订流程**：任何修订需文档化变更理由与影响范围，经确认后写入；修订时同步更新顶部「同步影响报告」与版本行。
- **版本策略**：语义化版本——MAJOR＝原则删除/重定义；MINOR＝新增原则/章节；PATCH＝措辞澄清。
- **合规评审**：每个功能在 converge 阶段核对宪法合规性；复杂度必须论证。
