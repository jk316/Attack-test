# 功能规格：PCAP 业务流量画像

**特性目录**: `specs/004-pcap-profile/`

**创建日期**: 2026-11-19

**状态**: 草案

**输入**: 用户描述："读取 PCAP/PCAPng 抓包文件，生成 UDP-only 口径的业务流量画像（结构化 JSON）。支持采样上限：最多读取前 N 个包（默认 50000），防止大文件内存爆炸；TCP/ICMP/非 IP 包不参与统计并在说明中注明被忽略数量。输出字段：top_dst_ips、top_dst_ports（各前 10）、packet_size_hist（分桶归一化概率）、iat_ms_stats（均值/中位数/P90，按 (dst_ip,dst_port) 相邻包时间差）、flow_stats（按 5 元组 + 30 秒 idle timeout 近似流数）、payload_len_stats（均值/中位数/P90）、notes（记录口径与一切无法解析的情况）。画像结果反哺 Agent 初始流量参数，形成「先画像、后攻击」的参数起点。"

## 用户场景与测试（必填）

### 用户故事 1 - 从抓包文件生成结构化 UDP 业务画像（优先级：P1）

操作员把既有业务流量的抓包文件交给系统，系统读取 PCAP/PCAPng 并生成结构化画像：主要目标 IP 与目标端口排行（各前 10）、包长分布直方图（按预定义桶归一化为概率）、包到达间隔（IAT）统计（均值/中位数/P90）、近似流数（含空闲超时参数）、UDP 负载长度统计（均值/中位数/P90），以及说明字段。统计口径限定 UDP：TCP、ICMP、非 IP 包一律不参与统计，被忽略数量写入说明；超大文件只读取前 N 个包（默认 5 万）防止内存爆炸，并在说明中注明截断事实。

**为什么是这个优先级**: 画像是「先画像、后攻击」的起点，也是本特性唯一的原始产出——没有画像，Agent 只能在参数空间中盲试，画像质量直接决定初始参数是否贴近真实业务。P1 独立交付即获得完整的画像能力，P2（反哺参数）完全建立在其上。

**独立测试方式**: 构造一个含 UDP（多目标、多端口、已知时间戳与包长分布）+ 少量 TCP/ICMP/非 IP 包的混合小抓包文件，调用画像并逐项核对全部输出字段：排行顺序与数量、直方图概率和为 1、IAT 与负载统计的均值/中位数/P90 与手工计算一致、流数与预期一致、notes 注明被忽略的包类型与数量；再用超过上限的大文件验证只读前 N 包且注明截断。仅此故事即可获得可用的画像 MVP。

**验收场景**:

1. **给定** 一个含 100 个 UDP 包（IP/端口/包长/时间戳分布已知）与 20 个 TCP、10 个 ICMP 包的 PCAP 文件，**当** 请求生成画像，**那么** top_dst_ips 与 top_dst_ports 按出现次数降序且各不超过 10 个、packet_size_hist 各桶概率之和为 1、iat_ms_stats 与 payload_len_stats 的均值/中位数/P90 与手工计算一致、flow_stats 含近似流数与空闲超时 30 秒、notes 注明被忽略的 TCP 与 ICMP 数量。
2. **给定** 一个超过采样上限（5 万包）的抓包文件，**当** 请求生成画像，**那么** 系统只读取前 5 万个包参与统计，notes 注明截断事实与上限值，生成过程内存占用有界。
3. **给定** 一个纯 TCP（无任何 UDP 包）的抓包文件，**当** 请求生成画像，**那么** 所有统计字段为空或零、notes 说明未发现 UDP 流量并注明被忽略的 TCP 数量。

### 用户故事 2 - 画像反哺 Agent 初始参数（优先级：P2）

Agent 拿到画像后，把画像特征映射为第一轮攻击的流量参数起点，而不是从默认值盲试：目标端口取自画像的主要端口、流数参考近似流数、包长采样自画像的包长分布、发送节奏参考 IAT 特征。画像的 notes（口径与忽略说明）同样对 Agent 可见，防止 Agent 把被忽略的 TCP/ICMP 特征误当成业务特征。

**为什么是这个优先级**: 这是画像存在的意义——闭环实验的「先想清楚再动手」。但它的价值完全依赖 P1 的画像质量，且画像→参数的映射方式可先由 Agent 基于注入的画像自主决策，因此排在 P1 之后；P3 的稳健性不新增画像能力，排在其后。

**独立测试方式**: 以一份画像 JSON 为上下文启动一轮 dry-run 实验（不发流量），观察 Agent 首轮流量参数提案：目标端口应出现在画像 top 端口集合中，流数与包长区间应与画像特征相关；人工核对提案与画像的一致性即可完成验证，无需真实发包。

**验收场景**:

1. **给定** 一份 top 目标端口为 53、123 的画像，**当** Agent 以该画像为上下文规划首轮 UDP 攻击参数，**那么** 首轮目标端口取自画像的 top 端口集合，而非无关端口。
2. **给定** 画像显示业务流数约 8、包长以 512–1024 为主，**当** Agent 规划首轮参数，**那么** 流数与包长与画像特征一致（流数不超过画像量级、包长落在画像主要区间）。
3. **给定** 画像的 notes 含「UDP-only 口径」与被忽略的 TCP/ICMP 数量说明，**当** Agent 使用画像，**那么** Agent 不把被忽略的 TCP/ICMP 流量特征误当成业务特征（例如不为 TCP 端口生成 UDP 攻击参数）。

---

### 用户故事 3 - 异常与边界稳健性（优先级：P3）

抓包文件可能不存在、损坏、无 UDP 内容、无法解析，或解析依赖缺失。系统必须返回结构完整（字段齐全、统计为空/零）且说明写明原因的结果，绝不崩溃；notes 是所有无法解析情况的唯一事实出口，调用方只读 notes 即可判断画像是否可用。

**为什么是这个优先级**: 稳健性不新增画像能力，但决定画像工具在真实脏数据环境（错误路径、截断文件、异构抓包）里是否可用；它是对 P1/P2 的加固，按价值排序放在 P3。

**独立测试方式**: 依次以不存在的路径、损坏的二进制文件、空文件、纯 TCP 文件调用画像，并在解析依赖不可用的环境下再调用一次，验证每次都返回完整字段结构且 notes 非空、进程不崩溃。仅此故事即可获得「永不崩溃、原因可查」的健壮性增量。

**验收场景**:

1. **给定** 不存在的文件路径，**当** 请求画像，**那么** 返回完整字段结构、notes 注明文件不存在，无异常抛出。
2. **给定** 一个损坏无法解析的文件，**当** 请求画像，**那么** 返回完整字段结构、notes 注明解析错误，无异常抛出。
3. **给定** 解析依赖不可用的环境，**当** 请求画像，**那么** 返回完整字段结构、notes 注明依赖不可用无法解析，无异常抛出。

## 边界情况

- 文件不存在：返回完整结构、统计为空/零，notes 注明文件不存在。
- 文件损坏或格式不支持：返回完整结构，notes 注明解析错误。
- 解析依赖缺失：返回完整结构，notes 注明依赖不可用、无法解析。
- 空文件或文件中无任何 UDP 包：统计字段为空/零，notes 说明未发现 UDP 流量并注明被忽略的包数量。
- 文件包数超过采样上限：只读取前 N 个包参与统计，notes 注明截断事实与上限值。
- 单包流（同一 (目标 IP, 目标端口) 只有 1 个包，无 IAT 可算）：IAT 统计保持空/零并在 notes 说明。
- 抓包内时间戳乱序：IAT 计算前按包到达时间排序。
- 非 IP 包（如 ARP、纯 L2 帧）：不参与统计，计入被忽略数量并在 notes 注明。

## 功能需求（必填）

- **FR-001**: 系统必须支持读取 PCAP 与 PCAPng 两种抓包文件格式，并生成结构化业务流量画像。
- **FR-002**: 系统必须支持包数上限控制（默认 50000）：超过上限时只读取前 N 个包参与统计，并在说明中注明已截断及上限值，防止大文件导致内存耗尽。
- **FR-003**: 画像统计必须只基于 UDP 包：TCP、ICMP 与非 IP 包一律不参与任何统计字段的计算，其被忽略数量必须在说明中注明。
- **FR-004**: 系统必须输出按出现次数降序排列的主要目标 IP 与主要目标端口排行，各取前 10 个。
- **FR-005**: 系统必须输出包长分布直方图：按预定义区间（≤64、≤128、≤256、≤512、≤1024、更大）分桶并归一化为概率，各桶概率之和为 1。
- **FR-006**: 系统必须输出包到达间隔（IAT）统计：均值、中位数、P90，单位为毫秒；间隔定义为同一（目标 IP, 目标端口）组合内相邻包的到达时间差，计算前按包到达时间排序。
- **FR-007**: 系统必须输出近似流数：按 5 元组（源 IP、源端口、目标 IP、目标端口、协议）区分流，同一 5 元组内相邻包时间间隔超过空闲阈值（默认 30 秒）视为新流，并在结果中给出所用空闲阈值。
- **FR-008**: 系统必须输出 UDP 负载长度统计：均值、中位数、P90。
- **FR-009**: 画像结果必须包含说明字段，记录：统计口径（UDP-only、IAT 计算方式）、采样截断、被忽略的包类型与数量，以及一切无法解析的情况（文件缺失、损坏、依赖缺失、无 UDP 内容等）。
- **FR-010**: 文件不存在、解析失败、依赖缺失等场景下，系统必须返回字段完整的结果（统计为空/零 + 说明写明原因），不得抛出未捕获异常中断调用方。
- **FR-011**: 画像结果必须以结构化数据交付给 Agent，使 Agent 能将画像特征（主要目标端口、包长分布、流数、IAT/负载特征）用作初始流量参数依据，形成「先画像、后攻击」的参数起点。
- **FR-012**: 被忽略的包（TCP/ICMP/非 IP）不得以任何方式影响统计字段（排行、直方图、IAT、流数、负载统计）的取值。

### 关键实体（涉及数据时填写）

- **业务流量画像**: 一次抓包分析的结构化结果：目标 IP/端口排行、包长直方图、IAT 统计、近似流数、负载统计、说明。
- **流**: 以 5 元组（源 IP、源端口、目标 IP、目标端口、协议）+ 空闲超时近似区分的通信序列。
- **包到达间隔样本（IAT）**: 同一（目标 IP, 目标端口）组合内相邻包的毫秒时间差序列。
- **包长桶**: 包长的预定义分档（≤64 / ≤128 / ≤256 / ≤512 / ≤1024 / 更大）。
- **说明（notes）**: 口径声明与全部异常/忽略/截断情况的文字记录，是画像可用性的唯一判断出口。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 对包含 50000 个 UDP 包的抓包文件，画像在 2 分钟内生成，且处理过程内存占用不超过 1 GB（参考普通工作站环境）。
- **SC-002**: 超过采样上限的文件 100% 只读取前 N 个包参与统计，说明中含截断注明；包数不超过上限的文件不出现截断说明。
- **SC-003**: 混合流量文件中，TCP/ICMP/非 IP 包被 100% 排除在所有统计字段之外，且 notes 中的被忽略数量与文件实际包类型计数一致（以构造文件验证）。
- **SC-004**: 对已知构造的时间序列，IAT 的均值/中位数/P90 与手工计算结果一致（误差不超过 0.01 毫秒），且严格按（目标 IP, 目标端口）分组计算。
- **SC-005**: 对构造的已知流场景（含 5 元组区分与 30 秒空闲断流的情况），近似流数计算结果 100% 与预期一致。
- **SC-006**: 连续 100 次异常输入（不存在路径、损坏文件、空文件、纯 TCP 文件）调用，进程零崩溃，每次均返回完整字段结构且 notes 非空。
- **SC-007**: 以画像为上下文运行时，Agent 首轮流量参数与画像主要特征（目标端口取自 top 端口集合、包长落在画像主要区间、流数不超过画像流数量级）一致的比例达到 90%（以 10 次带画像运行人工核对）。

## 假设

- 抓包文件来自已授权测试环境内的既有业务流量，分析过程只读不产生任何流量。
- 包时间戳可信；乱序时以排序后的顺序计算 IAT。
- 默认采样上限为 50000 包，截断取文件开头（时间序）的前 N 包。
- 画像交付 Agent 的方式为注入会话上下文，由 Agent 依据画像自主决定初始参数（确定性映射规则待澄清后落实）。
- 目标排行各取前 10 个；空闲阈值默认 30 秒。
- 抓包为常见以太网/IP/UDP 结构；其他封装视为无法解析并记入 notes。

## 需要澄清的问题（按影响排序）

1. **[需要澄清：画像反哺 Agent 初始参数的映射方式？]** 是注入上下文由 Agent 自由决策，还是按确定性规则映射（如目标端口取 top 端口第 1 名、包长按直方图概率采样、流数取近似流数）？这决定画像数据如何被消费与如何测试（接口与范围，影响最大）。
2. **[需要澄清：大文件截断策略？]** 只读文件开头的前 N 包会偏向抓包早期的流量特征；是否需要按时间均匀抽样，或支持按时间范围过滤后再统计。影响：画像代表性。
3. **[需要澄清：采样上限（50000）与空闲阈值（30 秒）是否需要可配置？]** 宪法要求「配置单一来源」，当前为内置默认；是否应放入统一配置文件或暴露为调用参数。影响：配置面与适用场景。
