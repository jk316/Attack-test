# 功能规格：拨测监控生命周期收归程序（RTT/HTTP 自动启动，Agent 只读）

**特性目录**: `specs/009-auto-start-monitors/`

**创建日期**: 2026-11-20

**状态**: 草案

**输入**: 用户描述："ping 和 HTTP monitor 都应该在后台由 main.py 启动时自动启动，而不是让 Agent 调用；Agent 只能读取拨测数据，不能启用/停用监控。"

## 用户场景与测试（必填）

### 用户故事 1 - 实验开始时监控自动就绪，无需 Agent 参与（优先级：P1）

实验员以任意方式启动实验（CLI 命令行，或 Web 控制台点击开始），后台 RTT（ping）监控立即由程序自动启动，目标为本次实验的目标 IP。整个实验过程中无需 Agent 调用任何"启动"工具，每轮流量工具的结果都携带有效观测数据。

**为什么是这个优先级**: 这是本次变更的核心诉求。现状把监控生命周期押在模型记性上——Agent 忘记调用 `start_ping_monitor` 时，整轮 `rtt_during` / `read_ping_stats` 为空，收敛判定失去数据依据。自动启动后观测数据每轮必有，直接消除这类失效模式。

**独立测试方式**: 运行一次 CLI 干跑实验（期间人为确保 Agent 不调用任何 start 工具），实验开始后立即通过 `read_ping_stats` 查询——应返回 `monitor_active=true` 且有样本；第一轮流量工具结果中的 `rtt_during` 非空。单独实现本故事即可交付「观测永远在线」的核心价值。

**验收场景**:

1. **给定** 配置了目标 IP 且通过 allowlist 预检，**当** 实验员启动实验（CLI 或 Web 控制台），**那么** ping 监控在实验运行前自动启动，无需 Agent 调用任何工具。
2. **给定** 实验运行中且 ping 监控正常，**当** Agent 调用任意流量工具（Scapy/Pktgen/TRex），**那么** 结果包含非空 `rtt_during`（含 `covers_attack_window` 判定）。
3. **给定** Agent 在整轮实验中从未调用监控启动工具，**当** 实验正常结束，**那么** 实验全程的观测数据依然完整（无空窗）。

---

### 用户故事 2 - 配置了 HTTP 业务目标时 HTTP 拨测同步自动启动（优先级：P2）

实验配置中填写了 HTTP 业务拨测目标（`http.url` 非空）时，程序在实验开始时同步自动启动后台 HTTP 拨测；未配置时保持不启动。流量工具结果中的 `http_during` 与 RTT 观测一样每轮可用。

**为什么是这个优先级**: HTTP 拨测与 RTT 是同一套失效模式、同一套修复逻辑，但只有配置了业务 URL 的实验才需要它，覆盖面小于 P1。

**独立测试方式**: 在 `experiment.json` 中配置 `http.url` 后启动实验，直接调用 `read_http_stats` 应返回 `monitor_active=true` 且有样本；流量工具结果中 `http_during` 非空。清空 `http.url` 再启动，`http_during` 为 null 且不产生拨测进程。

**验收场景**:

1. **给定** `http.url` 已配置，**当** 实验启动，**那么** HTTP 拨测自动启动，`read_http_stats` 可读到样本。
2. **给定** `http.url` 为空或缺失，**当** 实验启动，**那么** HTTP 拨测不启动，结果中 `http_during` 为 null。
3. **给定** HTTP 拨测运行中，**当** 实验结束或进程退出，**那么** 拨测线程/子进程被停止回收。

---

### 用户故事 3 - Agent 工具集只读化与生命周期清理（优先级：P3）

Agent 的工具列表中不再出现启动/停止监控的工具，只保留读取与单次探测；监控的停止由程序在实验结束、中断、进程退出时兜底完成。

**为什么是这个优先级**: 只读化是「生命周期单一归属」的组成部分——若保留 stop 工具，Agent 仍可在中途停掉监控造成观测空窗；清理兜底防止监控进程泄漏。它依赖 P1/P2 的自动启动才有意义。

**独立测试方式**: 构建 Agent 图后检查工具集（数量与名称），确认 4 个 start/stop 工具不存在、4 个读取/探测工具存在；运行实验后强杀进程，检查 fping/ping/curl 相关子进程在退出后即终止。

**验收场景**:

1. **给定** 实验图已构建，**当** 检查 Agent 工具列表，**那么** 不存在 `start_ping_monitor` / `stop_ping_monitor` / `start_http_monitor` / `stop_http_monitor`。
2. **给定** 实验图已构建，**当** 检查 Agent 工具列表，**那么** `read_ping_stats` / `read_http_stats` / `ping_rtt` / `http_probe` 存在。
3. **给定** 实验被 Ctrl-C 中断或 Web 控制台断开，**当** 进程退出，**那么** 两个监控的线程与子进程被停止（无残留 fping/ping/curl 进程）。

---

## 边界情况

- **目标 IP 未通过 allowlist**：main.py 预检即拒绝实验（现状行为不变）；若预检后校验仍失败，监控不启动、记录告警，实验继续。
- **`http.url` 为空或缺失**：不启动 HTTP 拨测，`http_during` 为 null（与现状「monitor 未运行」语义一致）。
- **`--trex-explore` 目录模式**：零流量模式，不启动任何监控。
- **监控启动失败**（fping 缺失、权限不足、URL 不可达）：记录告警但不阻断实验；ping 侧沿用 system ping 回退，观测字段为空时提示词指引 Agent 按「观测不可用」处理，不据此做参数决策。
- **Web 控制台连续启动两次实验**：启动前先停掉旧监控实例（幂等），避免重复线程与子进程。
- **CLI `--target-ip` 覆盖配置**：监控以覆盖后的目标为准（与预检一致）。
- **实验中途中断**（Ctrl-C / WS 断开 / 异常退出）：由程序侧 finally/清理路径停止两个监控。

## 功能需求（必填）

- **FR-001**: 实验开始时（CLI 入口与 Web 控制台入口均适用），系统必须自动启动后台 ping 监控，目标为本次实验的有效目标 IP（CLI 参数优先于配置）。
- **FR-002**: 当实验配置了 HTTP 拨测目标（`http.url` 非空）时，系统必须在实验开始时自动启动后台 HTTP 拨测；未配置时不得启动。
- **FR-003**: 监控目标必须通过 allowlist 校验后方可启动（安全优先，沿用 `validate_target`）。
- **FR-004**: `--trex-explore` 目录模式下系统不得自动启动任何监控。
- **FR-005**: dry-run 模式必须与 live 模式一致地自动启动监控（监控属观测行为，非攻击流量，不受 HITL 门禁约束）。
- **FR-006**: Agent 工具集不得包含启动/停止监控的工具；必须保留 `read_ping_stats`、`read_http_stats`、`ping_rtt`、`http_probe` 四个读取/单次探测工具。
- **FR-007**: 实验正常结束、被中断或进程退出时，系统必须停止两个监控并回收其线程与子进程。
- **FR-008**: 监控启动失败不得阻断实验；系统必须记录告警并继续运行，对应观测字段为空。
- **FR-009**: 系统提示词必须说明监控已由程序自动启动，引导 Agent 直接读取基线数据；不得再包含调用启动/停止监控工具的指引。
- **FR-010**: 监控参数（目标、间隔、超时、方法）必须来自配置单一来源（`experiment.json` / CLI 参数），不得在代码中硬编码默认值。
- **FR-011**: 本次变更必须配套单元/集成测试，覆盖「入口自动启动、只读工具集、退出清理、失败降级」行为。

### 关键实体（涉及数据时填写）

- **监控观测样本**：一次探测的结果——时间戳、RTT（或 TTFB/总耗时）、状态码（HTTP）、成功/失败标记；用于聚合出 `rtt_during` / `http_during`。
- **实验运行会话**：一次实验运行与一组监控实例的生命周期绑定——启动于实验开始前，终止于实验结束/进程退出；重复启动需先终止旧会话的监控。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 在监控正常运行的前提下，100% 的流量工具结果包含非空 `rtt_during`（不依赖 Agent 是否调用启动工具），`covers_attack_window` 判定照常给出。
- **SC-002**: Agent 工具集数量由 23 减为 19，且不存在任何启动/停止监控工具。
- **SC-003**: 实验进程退出后 5 秒内无残留的监控子进程（fping/ping/curl）。
- **SC-004**: 新增的自动启动/清理相关单元与集成测试全部通过，既有测试（除因删除工具而更新的用例外）保持通过。
- **SC-005**: 监控启动失败时实验完成率不受影响（失败仅降级观测，不阻断流程）。

## 假设

- 实验存在两个入口（CLI `src/main.py` 与 Web 控制台 `backend/experiment.py`），两者都必须自动启动监控——用户已确认服务器与本地均需覆盖。
- 监控属观测行为，不受 HITL 审批门禁约束（沿用现状：`start_ping_monitor` 本就不需 HITL）。
- 保留的读取/探测工具（`read_ping_stats` / `read_http_stats` / `ping_rtt` / `http_probe`）语义不变。
- 特性编号沿用项目全局编号（webui 分支已用至 008），本特性取 009，避免分支合并时编号冲突。
- 删除的 4 个 start/stop 工具在代码库中一并移除（非仅移出工具集），配套测试用例相应删除或改写。
