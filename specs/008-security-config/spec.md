## 用户场景与测试（必填）

### 用户故事 1 - 全项目统一的安全门控规则（优先级：P1）

无论流量来自 Scapy、Pktgen-DPDK 还是 TRex 脚本，所有产生流量的入口都必须执行同一套校验：目标在 allowlist 内、非广播/组播、无 src_ip 伪造、参数不超上限，并在真实发送前通过 HITL 人工审批。任何入口都不存在豁免捷径。

**为什么是这个优先级**: 宪法「四、安全优先（不可协商）」——本项目会产生真实网络流量，误伤或越权发送不可接受。门控统一规则是全部 001–007 功能的安全底线；规则缺失或不统一，任何一个入口都可能成为绕过点。

**独立测试方式**: 用同一组违规输入（非白名单 IP、广播地址、组播地址、伪造 src_ip、超上限参数）分别调用 Scapy、Pktgen、TRex 三类流量工具，逐一验证被拒绝或钳制且零流量；再用合法输入验证各工具在未审批时一律暂停。仅实现本故事即可形成「安全门控契约」MVP（可被其他所有功能引用）。

**验收场景**:

1. **给定** 目标 IP 不在白名单内，**当** 任一流量工具被调用，**那么** 工具拒绝执行、返回明确错误，且不发送任何包。
2. **给定** 目标为广播地址或组播地址，**当** 任一流量工具被调用，**那么** 校验拒绝且不发包。
3. **给定** 调用携带非空 src_ip，**当** 流量工具执行校验，**那么** 校验拒绝（源 IP 伪造被禁止）。
4. **给定** 参数超过上限（如 pps=100000、duration_s=120），**当** 工具执行，**那么** 参数被钳制到上限，且返回结果如实报告生效值。
5. **给定** 未获得人工批准，**当** 流量工具到达审批门禁，**那么** 执行暂停；无论 CLI 还是 Web 模式，均不允许自动放行。

---

### 用户故事 2 - 配置单一来源与命名预设（优先级：P2）

所有工具的默认参数以 `src/config/experiment.json` 为唯一来源，经环境变量在工具调用时读取；CLI 参数可覆盖默认值并立即生效；profiles 命名预设支持一键切换整组参数。

**为什么是这个优先级**: 宪法「六、配置单一来源」——单一来源避免配置漂移；调用时读取保证运行时覆盖生效；profiles 减少手改多个参数带来的出错面。低于 P1 是因为即使配置混乱，只要门控规则完好，安全底线仍成立。

**独立测试方式**: 修改 experiment.json 中的 duration_s 后无 CLI 参数运行一次实验，验证工具采用新默认值；以 `--profile high_pps` 运行验证预设覆盖；传入未知预设名验证报错并列出可用预设；显式 CLI 参数与预设冲突时验证 CLI 优先。

**验收场景**:

1. **给定** experiment.json 中 attack.duration_s=10，**当** 未传 CLI 参数启动实验且工具未显式传参，**那么** 工具采用 10 秒作为默认时长。
2. **给定** experiment.json 已定义 high_pps 预设，**当** 以该预设启动实验，**那么** pps/duration_s 采用预设值，其余参数沿用基础默认值。
3. **给定** 传入未定义的预设名，**当** 启动时，**那么** 报错并列出全部可用预设名。
4. **给定** 显式 CLI 参数与预设取值冲突，**当** 启动时，**那么** 显式 CLI 参数优先。
5. **给定** 配置文件中的默认值高于宪法上限，**当** 工具执行，**那么** 实际生效值仍受上限约束（上限不属于可调配置，只能约束生效值）。

### 用户故事 3 - 受控的审批旁路与风险提示（优先级：P3）

`--auto-approve` 与 dry-run 是合法工作流，但构成 HITL 门禁的旁路：必须默认关闭、显式启用、每次旁路都可见，并在文档中声明授权风险，防止"顺手"演变为未授权流量。

**为什么是这个优先级**: 门禁旁路是受控能力而非核心价值；优先级低于 P1（门禁本身）与 P2（配置体系）。但必须被规格显式约束，否则旁路会侵蚀 P1 的门禁可信度。

**独立测试方式**: 默认运行一次实验，验证每个流量工具调用都触发审批；`--auto-approve` 运行验证每次自动批准在输出中被明确标记；默认 dry-run 模式调用 Pktgen/TRex 工具，验证零流量；`--trex-explore` 全程验证零流量零审批。

**验收场景**:

1. **给定** 未启用 --auto-approve，**当** 实验触发流量工具，**那么** 每一次都必须经过人工审批。
2. **给定** 启用 --auto-approve，**当** 审批点被自动放行，**那么** 运行输出明确标记「自动批准（--auto-approve）」，提示操作员该次放行未经人工确认。
3. **给定** 默认（dry-run）模式，**当** 调用 Pktgen 或 TRex 工具，**那么** 仅编译/写脚本与语法检查，不产生任何网络流量。
4. **给定** --trex-explore 模式，**当** 整个探索过程运行，**那么** 全程零流量、零审批。

## 边界情况

- 白名单文件缺失、为空或解析失败：校验失败关闭（fail-closed），任何目标一律拒绝，绝不放行。
- 目标为 .255 广播地址或 224.0.0.0/4 组播地址：拒绝。
- 数值参数恰好等于上限：允许；超过上限：钳制到上限；非正值、端口为 0 或大于 65535：报错拒绝。
- pcap_replay 无 dst_ip 可校验（PCAP 自带目标）：豁免白名单校验，但保留 HITL 审批，并在系统提示中警告该豁免风险。
- TRex 脚本以域名、字符串拼接或编码方式构造目标 IP：静态 IP 扫描无法识别（尽力而为，非硬边界），由 HITL 展示脚本内容与警告兜底。
- --auto-approve 与实发模式（--pktgen-live / --trex-live）组合：形成全自动真实流量发送；文档必须警告该组合风险（是否禁止见待澄清问题 A）。
- experiment.json 中的默认值高于上限：工具内仍钳制；是否在启动时告警见待澄清问题 B。
- 环境变量被外部预置（绕过 main.py 注入）：工具以调用时读取为准；CLI 显式参数优先级最高。
- allowlist 在运行期被编辑：进程内加载一次，需重启进程生效。

## 功能需求（必填）

- **FR-001**: 所有会产生网络流量的工具（Scapy 发送类、Pktgen 洪水/扫描/序列/回放、TRex 实发执行）在发送前必须执行目标白名单校验；未通过校验必须拒绝执行且不得发送任何包。
- **FR-002**: 白名单必须由唯一配置文件管理；配置文件缺失、为空或解析失败时，所有目标校验必须失败关闭（fail-closed），不得放行任何目标。
- **FR-003**: 目标校验必须拒绝格式非法的 IP、广播地址与组播地址（224.0.0.0/4）。
- **FR-004**: 所有流量工具必须禁止源 IP 伪造：显式提供非空 src_ip 时校验必须拒绝。
- **FR-005**: Scapy 类流量参数必须以单一常量来源执行上限：pps≤20000、duration_s≤20、packet_size≤1024、flow_count≤100、iat_jitter_ms≤20、混合流量流数≤100。
- **FR-006**: 数值参数超过上限时必须钳制到上限并在结果中如实报告生效值；非正值、非法端口（0 或 >65535）必须报错拒绝。
- **FR-007**: Pktgen 速率必须不超过线速的 100%；Pktgen 攻击的同步等待时长必须封顶 60000 毫秒；要求目标 IP 的 Pktgen 技能必须强制目标非空且通过白名单校验。
- **FR-008**: 所有产生流量的工具在真实发送前必须经过人工审批门禁；未获批准不得执行发送。
- **FR-009**: 门控矩阵必须统一生效：arp_flood 与 pcap_replay 豁免白名单校验（L2 无 IP / PCAP 自带目标）但仍必须经过审批；stats_monitoring 与 safe_stop_and_reset 不产生流量、豁免审批。
- **FR-010**: TRex 实发执行必须经过人工审批，并在审批内容中展示脚本信息与检测到的 IP；默认 dry-run 仅写文件与语法检查，豁免审批。
- **FR-011**: TRex 脚本必须限定写入专用脚本目录且仅接受安全文件名；实发前必须对脚本做非白名单 IP 的静态扫描并在命中时拒绝执行，且必须向操作员声明该扫描为尽力而为、并非硬边界。
- **FR-012**: 目录探索模式必须在结构上只暴露不产生流量的工具集，保证该模式全程零流量、零审批。
- **FR-013**: 参数默认值必须以 experiment.json 为单一来源，经环境变量注入并在工具每次调用时读取；工具不得硬编码与之冲突的默认值。
- **FR-014**: CLI 参数必须能够覆盖配置默认值并立即生效；优先级为：显式 CLI 参数 > profiles 预设 > 基础配置。
- **FR-015**: 系统必须提供命名预设（profiles）以支持一键切换整组参数；使用未定义的预设名必须报错并列出全部可用预设。
- **FR-016**: 默认值、上限或门禁规则的任何变更必须同步更新所有文档化说明（工具 docstring、系统提示、README），保证文档与实际行为一致。
- **FR-017**: --auto-approve 必须默认关闭；启用时，每次自动批准必须在运行输出中明确标记，并在文档中声明其授权风险。
- **FR-018**: 安全校验必须内置于工具执行路径本身，不得依赖提示词约束或调用方的自觉。
- **FR-019**: dry-run 模式（Pktgen 与 TRex 的默认模式）不得产生任何网络流量。
- **FR-020**: 配置文件中的默认值不得高于宪法规定的上限；无论参数来自配置文件、环境变量还是 CLI，工具内的上限约束必须始终生效。

### 关键实体（涉及数据时填写）

- **安全策略**: 白名单条目、参数上限常量、门控矩阵的唯一事实来源，全项目共享、宪法级固定。
- **目标校验**: 对目标 IP 的校验契约（格式合法性、白名单归属、广播/组播拒绝、源 IP 伪造拒绝），所有流量工具统一复用。
- **实验配置**: experiment.json 的结构化配置（attack / pktgen / trex / profiles），默认参数唯一来源，不含上限定义。
- **审批决策**: 一次 HITL 门禁的处置结果（人工批准 / 人工拒绝 / 自动批准），来源可审计、展示可见。
- **运行模式**: dry-run / live / auto-approve / explore 四种模式组合，决定流量与审批门禁的实际生效路径。

## 待澄清问题（[需要澄清]，按影响排序）

### C1. --auto-approve 与实发模式的组合是否禁止（影响：全自动真实流量的可达性，最高）

当前 --auto-approve 可与 --pktgen-live / --trex-live 组合，形成"无人值守的真实流量发送"。

- **选项 A**：保持可用，但每次自动批准在输出中醒目警告（现状，依赖操作员自觉）——推荐为最低改动。
- **选项 B**：禁止 --auto-approve 与实发模式组合，组合时报错退出。
- **选项 C**：组合时要求额外的显式确认（如启动口令二次确认）。

### C2. 配置默认值超过上限时的处理策略（影响：配置错误的可见性）

当前 experiment.json 中高于上限的默认值会被工具静默钳制，操作员无从感知。

- **选项 A**：静默钳制（现状），仅在工具结果中报告生效值。
- **选项 B**：启动时检测并输出警告（列出超限项与被钳制后的值）——推荐。
- **选项 C**：启动时直接报错拒绝运行。

### C3. HITL 审批内容是否标准化（影响：审批效率与展示一致性）

各工具审批内容字段不一致：traffic_send/mixed_traffic_send 为 message+params，Pktgen 附 mode，TRex 附 filename/code_preview/warning。

- **选项 A**：统一审批内容结构（必含目标、参数快照、影响范围说明）——推荐。
- **选项 B**：维持现状，各工具自定。
- **选项 C**：统一结构 + 风险分级（普通流量发送 / 任意脚本执行两级展示）。

## 假设

- 参数上限是宪法级固定值，硬编码于工具常量中，不属于运行时可调配置；experiment.json 只能定义默认值，不能提高上限。
- 单一受信操作员模型（内网环境），多操作员并发与权限归属不在本规格范围（见 007 的待澄清 C2）。
- allowlist.json 与 experiment.json 在进程启动（模块导入）时加载一次，运行期修改需重启进程生效。
- 本规格为横切规格：各工具执行路径上的门禁调用点与参数钳制细节以 specs/002、005、006 为准；本规格规定它们必须共同满足的统一规则。
- 上限常量与门控矩阵以 CLAUDE.md「Key Conventions」与宪法「附加约束」为权威事实；若与 docstring 冲突，以代码常量的实际执行为准，并在修订时修复文档（宪法「文档真实性」）。
- --auto-approve 仅影响 HITL 审批环节，不豁免 allowlist 校验与参数上限（旁路范围限于审批）。
