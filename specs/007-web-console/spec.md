# 功能规格：Web 控制台（实时实验监控与人工审批）

**特性目录**: `specs/007-web-console/`

**创建日期**: 2026-11-19

**状态**: 草案

**输入**: 用户描述："Web 控制台——为闭环网络实验 Agent 提供基于浏览器的可视化操作界面。操作员打开一个暗色主题的单页控制台，通过实时双向通道（/ws/{client_id}）接收实验执行流（graph.ainvoke 异步桥接 → ws.send_json）推送的推理消息、工具调用与工具结果；当 Agent 在流量工具处触发 HITL 门禁时，控制台弹出审批弹窗，操作员点击『批准/拒绝』按钮，决定经队列（asyncio.Queue）回填给执行流，实验才继续执行；支持通过 POST /api/upload/pcap 上传 PCAP 供流量画像使用、通过 GET /api/experiment/status 查询实验状态，并可在页面上配置、启动与停止实验。核心安全要求：Web 端 HITL 门禁与 CLI 同源、不可被绕过。"

## 用户场景与测试（必填）

### 用户故事 1 - 实时观察实验并完成人工审批（优先级：P1）

操作员在浏览器中打开控制台，实时看到 Agent 的每一步推理、工具调用与工具结果；当 Agent 在流量工具处请求人工审批时，页面弹出审批弹窗并展示提示与参数，操作员点击「批准」或「拒绝」，实验按决定继续或中止。

**为什么是这个优先级**: 这是控制台存在的核心价值；同时承载宪法「四、安全优先」的 HITL 门禁——没有可用的审批通道，实验无法推进；门禁可被绕过，则会产生未授权流量。观察流与审批闭环缺一，其余功能（上传、状态）都失去意义。

**独立测试方式**: 本地启动服务并打开控制台，发起一次会调用流量工具的实验；观察消息逐条到达且类型区分正确；当审批弹窗出现时分别试验批准与拒绝，验证实验分别继续/中止。仅实现本故事即可构成 MVP（观察 + 审批）。

**验收场景**:

1. **给定** 服务已启动且控制台页面已打开，**当** 浏览器与服务建立实时通道，**那么** 页面立即显示连接成功状态与客户端标识。
2. **给定** 实验正在运行，**当** Agent 产生推理消息或调用工具，**那么** 消息以对应类型实时出现在消息面板，面板自动滚动到最新一条。
3. **给定** Agent 在流量工具处暂停并请求审批，**当** 审批请求（含提示与参数）被推送到控制台，**那么** 页面弹出审批弹窗，实验保持暂停且不发送任何流量。
4. **给定** 审批弹窗已显示，**当** 操作员点击「批准」，**那么** 决定被送达执行流，该次流量发送继续；**当** 操作员点击「拒绝」，**那么** 该次发送被中止且面板明确显示「审批拒绝」。
5. **给定** 操作员尚未作出任何决定，**当** 等待任意时长，**那么** 实验保持暂停，绝不自动放行（门禁不可被绕过）。

---

### 用户故事 2 - 配置、启停实验与 PCAP 上传（优先级：P2）

操作员在控制台侧栏填写目标 IP、最大迭代次数、无改善停止轮数，可选上传 PCAP 文件供流量画像，点击「启动实验」开始闭环实验；实验运行中可随时「停止实验」，并可在页面查看实验状态。

**为什么是这个优先级**: 补齐操作闭环，让操作员不必回到 CLI 即可完成整轮实验；PCAP 上传是「画像反哺初始参数」工作流在 Web 端的入口。低于 P1 是因为观察与审批是安全与价值的底线，而启停与上传是效率增强。

**独立测试方式**: 打开控制台，填写实验参数并启动；运行中再次启动验证互斥；上传一个 .pcap 文件并验证路径自动填入表单；停止实验后验证状态复位；用状态查询接口与页面显示比对。仅实现本故事即可构成「Web 端的实验编排」MVP。

**验收场景**:

1. **给定** 控制台已连接，**当** 操作员填写实验参数并点击「启动实验」，**那么** 实验启动，页面状态显示「运行中」，消息面板收到启动确认（含线程标识）。
2. **给定** 实验正在运行，**当** 再次点击「启动实验」，**那么** 系统拒绝启动并提示「实验已在运行中，请先停止当前实验」。
3. **给定** 操作员选择了扩展名为 .pcap/.pcapng/.cap 的文件，**当** 点击上传，**那么** 文件以唯一名称保存到服务端，返回的路径自动填入配置表单并可用于实验。
4. **给定** 实验正在运行，**当** 点击「停止实验」，**那么** 停止请求被受理，实验结束状态被推送，页面状态复位为就绪。
5. **给定** 实验处于运行中或空闲，**当** 查询实验状态，**那么** 得到与页面状态栏一致的结果（运行中/空闲）。

---

### 用户故事 3 - 连接状态可视与断线容错（优先级：P3）

页面顶部持续显示实时通道连接状态与实验状态徽章；连接断开时页面明确提示且不崩溃；客户端断线或发送无效消息不影响服务与正在运行的实验，重新连接后仍可获知真实状态。

**为什么是这个优先级**: 体验与稳定性兜底。状态可视降低操作员困惑，断线容错保证「断的是界面，不是实验」。低于 P1/P2 是因为不涉及核心数据流与安全门禁。

**独立测试方式**: 观察页面顶部的连接/状态徽章随连接与实验变化；手动断开网络或刷新页面后确认页面不崩溃；向服务发送无法识别的消息类型，验证收到错误提示且实验不受影响；重新打开页面查询状态与面板一致。

**验收场景**:

1. **给定** 控制台已打开且通道已建立，**当** 连接断开（网络中断或服务重启），**那么** 页面显示「未连接」状态且不崩溃。
2. **给定** 客户端向服务发送无法识别的消息类型或无效内容，**当** 服务收到该消息，**那么** 返回明确错误提示，且当前实验状态不受影响。
3. **给定** 客户端断线且实验仍在运行，**当** 重新打开页面并查询实验状态，**那么** 服务进程与实验不受断线影响，状态查询返回真实结果。

## 边界情况

- 实验运行中再次启动：拒绝启动并提示「实验已在运行中，请先停止当前实验」。
- 客户端断线/异常断开：服务安全清理该连接，不崩溃；实验继续由服务驱动（不自动停止）。
- 无效 JSON 或未知消息类型：向该客户端返回错误消息，不改变实验状态。
- 审批等待期间收到停止请求：停止语义生效，实验终止，审批不再阻塞。
- 实验运行异常：向客户端推送错误消息与实验结束消息，状态复位为空闲。
- 上传时未选择文件：返回「未选择文件」的失败提示。
- 多个浏览器同时打开：各自建立独立通道；同一服务同一时刻只允许一个实验（全局互斥）。
- PCAP 文件扩展名不在 .pcap/.pcapng/.cap 之列：前端不接受选择；服务器端是否做类型/大小校验见待澄清问题 C。
- 实验结束后的界面状态：状态复位为就绪，启动/停止按钮恢复可用。

## 功能需求（必填）

- **FR-001**: 系统必须提供一个可通过浏览器访问的静态单页控制台，采用暗色主题。
- **FR-002**: 系统必须为每个浏览器客户端建立独立的双向实时消息通道，并按客户端标识区分不同连接。
- **FR-003**: 系统必须在通道建立后立即向客户端推送连接成功状态（含客户端标识）。
- **FR-004**: 系统必须以实时消息流形式向客户端推送 Agent 的推理消息（角色、内容、工具调用列表）。
- **FR-005**: 系统必须以独立消息类型向客户端推送工具执行结果。
- **FR-006**: 系统必须向客户端推送实验生命周期状态消息（启动中、已结束、最终摘要）。
- **FR-007**: 前端必须实时渲染推送的消息，按消息类型差异化展示，并自动滚动到最新内容。
- **FR-008**: 操作员必须能够通过控制台发起实验，指定目标 IP、最大迭代次数、无改善停止轮数、PCAP 路径与日志路径。
- **FR-009**: 系统必须在已有实验运行时拒绝新的启动请求，并明确提示先停止当前实验。
- **FR-010**: 操作员必须能够请求停止运行中的实验。
- **FR-011**: 当 Agent 在流量工具处触发人工审批时，系统必须暂停执行并向客户端推送审批请求（含提示消息与参数快照）。
- **FR-012**: 操作员必须能够对每一次审批请求显式选择批准或拒绝。
- **FR-013**: 系统必须将操作员的审批决定送达对应的审批点后才允许继续执行；未收到决定前，实验必须保持暂停（HITL 门禁不可被绕过）。
- **FR-014**: 审批被拒绝时，系统必须中止该次流量发送，且工具结果必须明确标记为「被操作员拒绝」。
- **FR-015**: 系统必须提供 PCAP 文件上传能力，并将可接受的文件类型限制为 .pcap/.pcapng/.cap。
- **FR-016**: 上传的 PCAP 必须以服务端生成的唯一文件名落盘，并向客户端返回可在实验中引用的存储路径。
- **FR-017**: 系统必须提供实验运行状态（运行中/空闲）的查询能力。
- **FR-018**: 系统必须提供独立于实时通道的实验停止能力，作为通道外的补充。
- **FR-019**: 系统必须对未知或无效的客户端消息返回明确错误提示，且不得影响当前实验状态。
- **FR-020**: 客户端连接断开时，系统必须安全清理该连接且不导致服务或正在运行的实验崩溃；实验状态必须仍可通过查询获知。

### 关键实体（涉及数据时填写）

- **控制台会话**: 代表一个已连接的浏览器客户端；属性：客户端标识、连接状态、所属实验运行（同一时刻全局仅一个实验，会话仅消费消息流）。
- **实验运行**: 代表一次闭环实验；属性：目标 IP、最大迭代次数、无改善停止轮数、PCAP 路径、日志路径、运行状态、线程标识。
- **实时消息**: 推送单元的抽象；属性：消息类型（状态/AI 消息/工具结果/审批请求/审批响应/实验结束/错误）、角色、内容、工具调用列表。
- **人工审批请求**: 代表一次 HITL 门禁暂停；属性：提示文本、参数快照、操作员决定（批准/拒绝/未决）。
- **PCAP 上传文件**: 属性：原始文件名、唯一存储路径、字节大小、文件类型。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 从通道建立到客户端收到连接确认消息的延迟小于 1 秒。
- **SC-002**: 在本地网络环境下，单条消息从产生到出现在控制台面板的延迟小于 500 毫秒。
- **SC-003**: 审批请求在 Agent 暂停后 1 秒内展示给操作员；操作员作出决定后 1 秒内送达执行流。
- **SC-004**: 100% 的流量工具调用在执行前必须有匹配的人工审批决定，无任何一条绕过门禁（0 例外）。
- **SC-005**: 审批被拒绝后，该次工具调用的流量产生量为 0（可验证零包发出）。
- **SC-006**: 操作员无需文档辅助，可在 2 分钟内完成「打开页面 → 发起一次实验」。
- **SC-007**: 单次实验推送 1000 条消息时，面板渲染无遗漏、无卡顿。
- **SC-008**: 实验状态查询在运行期间 99.9% 的请求响应时间小于 100 毫秒。
- **SC-009**: 实验运行中收到的二次启动请求 100% 被拒绝并给出明确提示。
- **SC-010**: 10MB 以内的 PCAP 文件在本地网络环境下 5 秒内完成上传并返回可用路径。

## 待澄清问题（[需要澄清]，按影响排序）

### C1. 控制台的身份认证与授权（影响：安全边界，最高）

当前控制台无任何登录认证，任何能访问服务地址的人都能查看实验消息并批准流量发送。

- **选项 A**：v1 不引入认证，仅限受信内网环境使用（与 CLI 一致）——推荐，范围最小。
- **选项 B**：增加简单令牌/密码校验（如启动时配置的访问口令）。
- **选项 C**：引入完整账号体系与角色权限。

### C2. 多客户端场景下审批决定的归属（影响：并发语义与误操作风险）

当前任意已连接客户端都可以对审批请求作答，即使它不是发起实验的那个客户端。

- **选项 A**：保持现状（受信单操作员环境，多窗口仅用于观察）——推荐。
- **选项 B**：仅发起实验的客户端可作答，其余客户端只读观察。
- **选项 C**：任一客户端作答后，其余客户端仅同步显示结果。

### C3. PCAP 上传的服务器端校验（影响：范围/资源风险）

当前仅前端限制扩展名，服务器端未校验文件类型与大小上限。

- **选项 A**：服务器端增加扩展名与大小上限校验（如 ≤100MB）——推荐。
- **选项 B**：维持现状（仅前端限制）。
- **选项 C**：进一步增加内容嗅探校验（magic bytes 识别 PCAP/PCAPng）。

## 假设

- 操作员为受信内网用户，与 CLI 同一操作员角色（对应待澄清 C1 的默认选项 A）。
- 服务单机部署，同一时刻全局仅一个实验运行（多浏览器仅作观察窗口）。
- 客户端断线后实验不自动停止，由服务继续驱动；操作员可通过停止接口或重新连接处置。
- v1 仅支持桌面浏览器上的暗色单页控制台，不做移动端适配。
- HITL 门禁规则（哪些工具需要审批）、allowlist 与参数上限由 specs/002-scapy-traffic-tools、005-pktgen-integration、006-trex-integration、008-security-config 定义；本规格只规定控制台如何呈现与转达审批决定，不新增、不豁免任何门禁。
- 静态页面与样式、脚本由服务同源提供，无独立前端构建流程。
- 消息面板展示的推理内容为纯文本渲染（含必要的转义），v1 不渲染富文本。
