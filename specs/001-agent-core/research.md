# 阶段 0 研究：核心闭环 ReAct Agent 与运行模式

**特性**: `specs/001-agent-core/` | **日期**: 2026-11-19 | **输入**: 规格澄清项与关键技术选型

## 决策记录

> 格式：决策 / 理由 / 备选方案。前三条为规格 [需要澄清] 项的推荐默认（Lead 指定采纳）。

### D1（澄清 001-1）收敛早停 = 运行时硬裁决

**决策**: 收敛早停由运行时硬性裁决——每轮结束后，运行时以工具实测的 avg_rtt_ms 与 loss_pct 计算奖励、更新连续无改善计数，达到 `no_improve_limit` 即强制终止；`max_iters` 无条件终止不变。同时保留提示词中的停止条件文字，引导模型提前收敛与总结（双保险，但以硬裁决为准）。

**理由**: 消除模型不遵守提示词带来的不确定性，使 SC-003（确定性序列下必然按时停止）可测试、可承诺；宪法原则二「闭环驱动」要求有终点的收敛。现状 `src/agent/state.py` 已实现 `compute_reward` / `update_best` / `check_stop_condition` 但未接入主循环，接入成本低。硬裁决仅在实验模式启用（目录探索无 RTT 观测语义）。

**备选方案**: A) 保持提示词软约束（现状）——模型可能不停，SC-003 不可测，运行成本不可控；B) 仅运行时裁决、删除提示停止条件——模型失去提前总结的引导，输出质量下降。均不采纳。

### D2（澄清 001-2）奖励公式统一为单一公式

**决策**: 全链路统一为 `reward = avg_rtt_ms + loss_pct × 10`（采用系统提示中已生效的公式），同步修正 `src/agent/state.py` 中遗留的 `avg_rtt_ms − loss_pct × 0.1`，使提示、运行时计算、硬裁决使用同一公式。

**理由**: 提示中的公式已在多轮生产中指导模型，且与「丢包率本身是有效攻击信号」的产品语义一致（系统提示明确要求把 loss 上升视为攻击效果）；state.py 的旧公式从未接入主循环，属于历史遗留。统一后 FR-006/FR-016 可精确验证。

**备选方案**: A) 采用 `avg − loss×0.1`——与产品语义（loss 是攻击效果而非惩罚）冲突；B) 保留两处并存——正是 FR-016 标记的判定口径混乱来源。均不采纳。

### D3（澄清 001-3）启动前预检目标与预算

**决策**: `main()` 在构建图之前执行预检：(1) 目标 IP 位于 allowlist（复用 `validate_target` 或等价校验）；(2) `max_iters ≥ 1`、`no_improve_limit ≥ 1` 为正整数；(3) 互斥组合（--trex-explore × --trex-live，现状已实现）。任一不合规打印明确中文错误并**非零退出**，不发起模型请求。

**理由**: 快速失败节省 token 与时间，符合宪法「安全优先」——非法目标应在任何动作前被拦截，而非等首次工具调用暴露。预检复用工具层校验逻辑，不引入第二套 allowlist 判定。

**备选方案**: A) 维持现状（工具调用时暴露）——体验差、已付 token 成本；B) 只预检 allowlist 不检预算——不完整。均不采纳。

### D4 reasoning_content 补丁评估

**决策**: 保留现状的双向 monkey-patch（入站 `_convert_dict_to_message` 提取、出站 `_convert_message_to_dict` 回传），不改动实现；新增回归测试覆盖多轮（≥3 轮）无 400 类错误（SC-002）。

**理由**: 现状已满足 FR-009；补丁属于对上游行为的适配，重写收益为零。若上游 langchain-openai 原生支持 reasoning_content 回传，再评估移除补丁（记录为跟进项，不在本特性范围）。

**备选方案**: 升级依赖等待上游修复——版本不可控、阻塞交付。不采纳。

### D5 硬裁决的观测数据来源

**决策**: 硬裁决的「本轮改善」判定只取工具返回的实测数据——优先 `rtt_during.avg_rtt_ms`/`loss_pct`（003 规格定义的观测字段），回退到 `read_ping_stats` 的 `avg_rtt_ms`/`loss_pct`；工具返回观测不可靠（如 `covers_attack_window=false`）时，该轮**不计入无改善判定**（既不判改善也不计恶化），并在日志标注。

**理由**: 宪法「可观测驱动」——无可靠观测回馈的动作不得作为决策依据；避免把观测未覆盖的轮次误判为「无改善」而提前终止。

**备选方案**: 依赖模型自述效果——不可靠、可被幻觉污染。不采纳。

### D6 硬裁决的适用范围

**决策**: 硬裁决与奖励计数仅适用于实验模式；目录探索模式（mode=catalog）没有 RTT 观测语义，仅受 `max_iters` 与图超步预算（`max(25, max_iters+5)`，现状）约束，保持零流量零审批自治。

**理由**: 目录模式的目标是生成数量达标（catalog_target），「无改善」概念不适用。

**备选方案**: 目录模式也引入计数——语义牵强。不采纳。

## 其余技术选型（现状确认，无改动）

- **模型接入**: `ChatOpenAI` → `https://api.deepseek.com`，模型名 env `LLM_MODEL`（默认 deepseek-chat），temperature=0.7、reasoning_effort=high、thinking enabled。保持现状。
- **图构建**: `create_agent` + `MemorySaver` 检查点；超步预算由调用方经 invoke config 传入（现状 `_recursion_limit`）。保持现状。
- **HITL 通道**: CLI 同步轮询 + `input()`（本特性）；Web 控制台异步队列由 007 规格覆盖，本特性只保证 `build_graph` 对两种宿主契约一致。
- **配置注入**: experiment.json → main.py 设 env → 工具调用时读取（现状）；profiles 深合并（attack/pktgen/trex 三段）。保持现状。
