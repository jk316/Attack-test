## 用户场景与测试（必填）

### 用户故事 1 - 实验员通过 CLI 运行闭环实验并逐轮审批流量（优先级：P1）

实验员在终端启动 CLI 实验（指定目标 IP、最大轮数与可选 PCAP/指令），Agent 自主执行闭环：启动后台监控 → 读取攻击前基线 → 提议流量参数并**暂停等待人工审批** → 获批后发送流量 → 观测攻击窗口内的 RTT 与丢包 → 记录本轮结果 → 基于实测数据决策下一轮，直至满足停止条件后输出实验总结。

**为什么是这个优先级**: 闭环自主探索是本项目的核心价值，也是宪法原则二「闭环驱动」的直接载体——没有「行动→观测→决策」闭环与安全审批门禁，整个产品不成立。P1 是其余一切功能的基础。

**独立测试方式**: 在授权测试网络（或 mock 网络的集成测试床）中运行 CLI 实验（如 `--target-ip <allowlist 目标> --max-iters 3`），观察「审批弹窗 → 批准/拒绝 → 结果回传 → 下一轮决策 → 总结输出」全链路即可完整验证，无需依赖 Web 控制台或硬件加速器。

**验收场景**:

1. **给定** 已配置有效 API 密钥与 allowlist 目标，**当** 实验员以 `--max-iters 3` 启动 CLI 实验且 Agent 提议发送流量，**那么** 终端显示审批请求，包含操作说明与完整参数明细，并等待操作员输入。
2. **给定** 审批请求已显示，**当** 操作员输入 `y`，**那么** 该轮流量发送执行，工具返回包含攻击窗口 RTT 观测的结果，Agent 继续下一轮决策。
3. **给定** 审批请求已显示，**当** 操作员输入 `n`，**那么** 不发送任何流量，工具返回拒绝结果，Agent 据此调整策略而不是原样重复同一请求。
4. **给定** 实验满足停止条件，**当** 最后一轮结束，**那么** 终端输出实验总结，提示结果已写入日志文件，且后台 ping 监控进程被清理。

### 用户故事 2 - 实验员控制运行预算并依赖收敛早停（优先级：P2）

实验员通过配置文件或命令行设定 `max_iters` 与 `no_improve_limit`。Agent 在连续 `no_improve_limit` 轮无改善时提前收敛，在达到 `max_iters` 时无条件停止；默认参数来自统一配置文件，命令行覆盖配置。

**为什么是这个优先级**: 没有预算上限的自主 Agent 会无限消耗 token、时间并反复发送无效流量；早停让实验可收敛、成本可预测，是「闭环」概念的终点。它依赖 P1 的闭环骨架，但可独立验证与交付。

**独立测试方式**: 用确定性的模拟模型/工具序列驱动 Agent，构造「连续无改善」的 RTT 序列与「固定最大轮数」两种场景，观察停止时机即可验证；再用命令行覆盖配置值验证注入链优先级。

**验收场景**:

1. **给定** `no_improve_limit=3` 且最近 3 轮的 RTT/丢包综合指标均未超过历史最优，**当** 第 3 轮无改善的结果产生，**那么** Agent 停止并提出实验总结。
2. **给定** `max_iters=5`，**当** 运行到达第 5 轮，**那么** 无论本轮是否改善都必须停止。
3. **给定** 配置文件写入 `max_iters=20`、`no_improve_limit=5`，**当** 实验员以 `--max-iters 6 --no-improve-limit 2` 启动，**那么** 本次运行采用 6/2（命令行优先于配置文件）。
4. **给定** 实验员未提供相应命令行参数，**当** 运行启动，**那么** 工具与系统提示使用配置文件注入的默认参数。

### 用户故事 3 - 研究员以目录探索模式无人值守生成 TRex 攻击目录（优先级：P3）

研究员运行 `--trex-explore` 让 Agent 只使用脚本目录生成能力：全程不发送任何流量、不弹出任何审批，生成不少于指定数量的带中文注释攻击脚本目录，并把目录摘要持久化为带时间戳的文件，多次运行互不覆盖。

**为什么是这个优先级**: 这是知识沉淀型扩展价值，且「零流量、零审批」使其可无人值守批量运行；核心实验闭环不依赖它。放在 P3，但它是「三模式选择」完整性的组成部分。

**独立测试方式**: 运行 `--trex-explore --catalog-target 10`，验证全程无审批中断、可调用工具集仅限目录生成工具、运行结束后 `output/` 下出现 `trex_attack_catalog_<时间戳>.md` 且列出 ≥10 个脚本条目，即可完整验证。

**验收场景**:

1. **给定** 以 `--trex-explore` 启动，**当** Agent 尝试调用工具，**那么** 只有目录生成相关工具可被调用，任何流量工具都不在可用集合中。
2. **给定** 探索运行正常结束且最终消息非空，**当** 运行收尾，**那么** 系统把摘要写入 `output/trex_attack_catalog_<时间戳>.md`，文件名含时间戳，历史运行的摘要不被覆盖。
3. **给定** 实验员同时指定 `--trex-explore` 与 `--trex-live`，**当** 启动，**那么** 系统立即报错退出，不执行任何后续动作。

## 边界情况

- **API 密钥缺失或为空** → 系统拒绝启动并给出明确错误，不发起任何模型请求。
- **非交互终端（无可用输入，如管道 EOF）** → 审批默认拒绝（安全优先），运行可继续，Agent 收到拒绝结果。
- **审批被反复拒绝** → Agent 调整参数后重新提交审批，不重复提交相同请求。
- **`no_improve_limit ≤ 0` 或 `max_iters ≤ 0`** → 按配置语义以最小轮数执行；是否需要在启动前预检并报错，见 FR-017 的澄清标记。
- **目标 IP 不在 allowlist** → 首次流量/监控动作即被工具层校验拒绝，Agent 收到明确错误；运行不产生任何流量。
- **多轮推理内容回传异常（补丁失效场景）** → 运行失败必须可诊断（明确错误信息），不得静默丢弃推理内容。
- **LLM 网络错误 / 服务不可用** → 运行报错退出，清理逻辑仍执行，无残留监控进程。
- **`--trex-explore` 与 `--trex-live` 同时出现** → 启动阶段报错退出，二者互斥。
- **配置文件缺失或损坏** → 回退内置默认值继续启动，不崩溃。
- **目录探索最终消息为空** → 不写摘要文件，运行正常结束并提示。

## 功能需求（必填）

- **FR-001**: 系统必须提供统一的 Agent 构建入口，按运行模式选择系统提示与工具集：实验模式使用闭环实验提示与完整工具集；目录探索模式仅暴露目录生成工具并强制不发送流量。
- **FR-002**: 实验模式下，系统必须驱动 ReAct 闭环：读取基线 → 提议流量参数 →（经审批）发送流量 → 观测 RTT/丢包 → 记录本轮结果 → 基于观测决策下一轮，直至满足停止条件。
- **FR-003**: 系统必须在运行开始时向 Agent 注入运行上下文：目标 IP、最大轮数、无改善停止阈值、日志路径、可选 PCAP 路径与可选用户自由指令。
- **FR-004**: 流量类工具的调用必须暂停运行并请求人工审批（HITL）；只有操作员明确批准后才允许继续发送；拒绝时该轮不发送任何流量，并向 Agent 返回拒绝结果。
- **FR-005**: 系统必须支持「自动批准」开关；未开启时以交互提示征求审批；无法读取操作员输入时（如无终端输入）必须默认拒绝。
- **FR-006**: 系统必须在连续无改善轮数达到 `no_improve_limit` 时终止运行（收敛早停），并在轮数达到 `max_iters` 时无条件终止。[需要澄清 1/3：收敛早停的裁决机制——由运行时硬性裁决（每轮校验计数、达标即强制停止）还是由提示词约束模型自主停止？当前实现以提示词软约束为主，存在模型不主动停止的可能；若要求硬性裁决将影响架构与测试方式。]
- **FR-007**: `max_iters` 与 `no_improve_limit` 必须可配置：默认值来自统一配置文件，命令行参数优先于配置；配置缺失时使用内置默认（20 与 5）。
- **FR-008**: 系统必须把配置文件中的攻击与硬件默认参数经环境变量注入工具层，工具在调用时读取，确保命令行覆盖实时生效、工具不硬编码与配置冲突的默认值（配置单一来源）。
- **FR-009**: 多轮对话中，模型返回的推理内容（reasoning_content）必须被保留，并在后续每一轮请求中原样回传，保证第 2 轮及以后的对话不因推理字段缺失而失败。
- **FR-010**: 未配置任何可用 API 密钥时，系统必须拒绝启动并给出明确错误信息。
- **FR-011**: 目录探索模式必须全程不产生流量、不触发审批中断；结束时把生成的脚本目录摘要持久化为带时间戳的文件，每次运行的摘要不得覆盖历史运行。
- **FR-012**: 目录探索模式与真实执行开关必须互斥；同时指定时系统必须在启动阶段报错退出。
- **FR-013**: 系统必须记录 LLM 输入与输出日志：结构信息输出到控制台，完整内容写入日志文件；并提供提高控制台详细度的开关。
- **FR-014**: 运行结束（包括异常结束）必须清理后台监控进程，不遗留残留进程。
- **FR-015**: 系统必须支持命名预设（profile）：以一条命令切换整组参数；预设名不存在时必须报错并列出可用预设。
- **FR-016**: 「无改善」的判定必须采用单一、明确的奖励公式，且系统提示中的口径与运行时判定逻辑一致。[需要澄清 2/3：奖励公式口径——当前系统提示定义 reward = avg_rtt_ms + loss_pct × 10，而运行时状态模块中的函数使用 avg_rtt_ms − loss_pct × 0.1，二者不一致会导致「无改善」判定结果不同，需统一后 FR-006 才可精确验证。]
- **FR-017**: 系统必须在启动前校验关键参数（目标 IP 位于 allowlist、预算参数为正整数），不合规时拒绝启动并给出原因。[需要澄清 3/3：启动前预检——当前实现不预检目标 IP 与预算合法性，违规值在首次工具调用时才暴露；是否要求启动即报错将影响用户体验与测试方式。]

### 关键实体（涉及数据时填写）

- **实验运行**：一次从启动到总结的完整 Agent 会话；含运行模式、预算（max_iters / no_improve_limit）、目标、日志路径与最终总结。
- **运行模式**：构建层的「实验 / 目录探索」两种提示与工具集组合，以及「CLI / Web 控制台」两种运行宿主；三种运行形态共用同一构建契约。
- **迭代轮次**：一轮「行动 → 观测 → 记录 → 决策」的最小闭环单元；RTT 与丢包是轮次间比较的依据。
- **HITL 审批**：流量动作的人工授权点，含操作说明与参数明细、批准/拒绝两种结果；拒绝结果回传给 Agent。
- **参数配置**：单一来源的配置文件（含攻击/硬件参数与命名预设），经环境变量在调用时注入工具。
- **对话消息**：Agent 与模型的往返消息流，含模型推理内容字段，必须在多轮间完整保留。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 本地构建阶段（不依赖模型响应）在 10 秒内完成并发起首个模型请求。
- **SC-002**: 多轮（≥3 轮）运行中，每一轮均不出现因推理内容缺失导致的请求失败（0 次 400 类错误）。
- **SC-003**: 在确定性「恒无改善」测试序列下，运行在不晚于 `no_improve_limit` 次连续无改善后终止；在确定性「恒继续」序列下，运行在 `max_iters` 时终止。
- **SC-004**: 被拒绝审批的轮次产生 0 个发送报文（可通过工具返回值与流量统计验证）。
- **SC-005**: 以命令行参数启动时，工具实际使用的默认值与命令行值一致（配置覆盖链正确率 100%，以日志与工具返回值抽样验证）。
- **SC-006**: 目录探索运行全程 0 流量、0 审批，摘要文件成功写入且文件名含时间戳；连续两次运行的摘要文件互不覆盖。
- **SC-007**: 无论正常或异常结束，运行结束后无残留 ping 监控进程。
- **SC-008**: 未知预设名与互斥参数组合在启动后 1 秒内报错退出，并给出可用项/原因说明。

## 假设

- 运行环境可访问 DeepSeek API 且密钥有效；模型行为符合其 API 契约。
- 交互式 CLI 在带终端的授权环境使用；无终端输入时默认拒绝审批（安全优先）。
- Web 控制台运行形态的细节（WebSocket 消息流、异步审批队列）由 007-web-console 规格覆盖；本规格只约束统一构建入口对三种宿主的契约一致性。
- Pktgen 与 TRex 工具内部的安全矩阵分别由 005-pktgen-integration 与 006-trex-integration 规格覆盖，本规格不重复。
- `src/llm/` 下的独立 LLM 包装器与演示脚本不属于 Agent 运行时路径，不在本规格范围内。
- 实验网络环境已获授权向 allowlist 目标发送流量。
- 「无改善」以 RTT 与丢包的综合指标衡量；具体公式按 FR-016 澄清结果统一。
