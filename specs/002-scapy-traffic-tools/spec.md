# 功能规格：Scapy 流量工具集

**特性目录**: `specs/002-scapy-traffic-tools/`

**创建日期**: 2026-11-19

**状态**: 草案

**输入**: 用户描述："Scapy 流量工具集：traffic_send（单协议 UDP 流量）、mixed_traffic_send（多协议混合流量）、ping_rtt（单次 RTT 探测）、log_result（JSONL 实验日志）四个工具；参数钳制上限 pps=20000 / duration_s=20 / packet_size=1024 / flow_count=100 / iat_jitter_ms=20 / MAX_STREAMS=100；allowlist 拒绝；multi-flow 与抖动；JSONL 日志。"

## 用户场景与测试（必填）

### 用户故事 1 - 实验员发送受控单协议 UDP 流量（优先级：P1）

实验员（或 Agent）通过 traffic_send 向 allowlist 目标发送单协议 UDP 流量，指定端口、时长、速率、报文大小、并发流数与抖动；系统自动把超限参数钳制到安全上限，多流之间以不同源端口轮转发包，结果包含实际生效参数与实测速率。

**为什么是这个优先级**: 单协议流量是闭环实验最基本的「行动」单元，其它发送工具都建立在其参数与安全模型之上；同时它承载 allowlist 与 HITL 两道安全门禁。它是可独立交付的最小闭环能力。

**独立测试方式**: 在授权测试网络对 allowlist 目标发流（如 pps=100、duration=2、flow_count=3），核对返回的钳制参数、报文总数、各流计数与实际速率；再用越限参数与非法目标验证钳制与拒绝行为，即可完整验证。

**验收场景**:

1. **给定** allowlist 目标与合法参数，**当** 调用 traffic_send(pps=100, duration_s=2, flow_count=3) 且获审批，**那么** 3 条流各用不同源端口轮转发包，返回 packets_sent.total>0 且 per_flow 覆盖 3 条流。
2. **给定** pps=999999、duration_s=999、packet_size=4096、flow_count=500、iat_jitter_ms=100，**当** 调用且获审批，**那么** 实际按 pps=20000、duration_s=20、packet_size=1024、flow_count=100、iat_jitter_ms=20 钳制后的参数发送，返回值反映钳制后参数。
3. **给定** 目标不在 allowlist（或为广播/组播地址），**当** 调用，**那么** 拒绝执行、发送 0 报文并返回明确错误。

---

### 用户故事 2 - 实验员模拟多协议混合业务流量（优先级：P2）

实验员通过 mixed_traffic_send 提交 JSON 流量规格，一次性发送多协议（TCP/UDP/ICMP/DNS 等）多流混合流量；系统校验协议白名单、自动补齐缺失百分比、强制把发送目标覆盖为工具参数指定的 IP，并按百分比加权随机选流发送。

**为什么是这个优先级**: 混合流量更贴近真实业务形态，能探索目标对不同协议组合的敏感性，是 P1 的能力扩展；但仅交付 P1 已可跑通闭环实验，故为 P2。

**独立测试方式**: 提交包含多条流（含缺百分比流）的合法规格与若干非法规格（协议越白名单/总和不为 100/注入特征），验证百分比补全、目标覆盖、按占比发送与拒绝行为，即可完整验证。

**验收场景**:

1. **给定** 合法规格（两条流 percentage 60/40），**当** 调用且获审批，**那么** 实际发送的流占比近似 60/40，结果含 per_stream 计数。
2. **给定** 规格中一条流 percentage 缺失（另一条为 40），**当** 调用且获审批，**那么** 缺失流被自动补为 60，总和为 100 后正常发送。
3. **给定** 规格中某条流的 IP.dst 为任意值（如 8.8.8.8），**当** 调用且获审批，**那么** 实际发送目标一律为工具参数的 dst_ip，规格内声明的 IP 被忽略。
4. **给定** 协议越白名单 / 百分比总和不 100 / 含注入特征的规格，**当** 调用，**那么** 整个规格被拒绝并给出具体原因，0 报文发送。

---

### 用户故事 3 - 实验员探测 RTT 并留存每轮实验日志（优先级：P3）

实验员通过 ping_rtt 对 allowlist 目标做单次探测获得平均 RTT 与丢包率；通过 log_result 把每轮参数与观测结果追加写入 JSONL 日志（含时间戳），供实验复盘与数据分析。

**为什么是这个优先级**: 探测与记录是闭环「观测」与「可追溯」的支撑件，是宪法「可观测驱动」的落地；它们不直接产生攻击效果，优先级低于两个发送工具。

**独立测试方式**: 对 allowlist 目标 ping 一次核对返回字段与全丢包语义；连续调用 log_result 两次验证追加写入与时间戳；用不存在的日志目录验证失败语义，即可完整验证。

**验收场景**:

1. **给定** allowlist 内可达目标，**当** 调用 ping_rtt(count=4)，**那么** 返回 avg_rtt_ms、loss_pct 与收发计数，且在超时时间内完成。
2. **给定** 目标全部探测丢失，**当** 调用 ping_rtt，**那么** loss_pct=100 且 avg_rtt_ms 记为无穷大。
3. **给定** 合法日志目录与两条记录，**当** 依次调用 log_result，**那么** 日志文件追加两行合法 JSON，每行含轮次/参数/RTT/丢包与 UTC 时间戳，历史行不被覆盖。
4. **给定** 不存在的日志目录，**当** 调用 log_result，**那么** 返回失败且不创建文件。

---

## 边界情况

- **速率/时长/报文大小/流数 ≤0，抖动 <0** → 拒绝并返回错误（钳制只处理超上限，不掩盖非法下限）。
- **dst_port 不在 1–65535** → 拒绝。
- **目标 IP 格式非法 / 广播（.255）/ 组播（224–239）/ 不在 allowlist** → 拒绝。
- **allowlist 文件缺失或损坏** → 回退内置默认列表；allowlist 为空 → 拒绝一切目标。
- **src_ip 提供任何非空值** → 拒绝（禁止源 IP 伪造）。
- **高权限发送通道不可用** → 自动降级到无需特权通道；仍不可用则尝试最后手段；全部失败 → 返回失败。
- **混合规格非法**：JSON 无法解析 / 超长（>10000 字符）/ 流数 <1 或 >100 / 协议不在白名单 / 重复 stream_id / 字段含注入特征 / 百分比非法或总和不 100 → 整规格拒绝并说明原因。
- **混合规格缺百分比且显式百分比之和已 ≥100** → 拒绝（无补齐空间）。
- **发送过程中收到中断信号** → 停止发送并返回已发送统计（是否标注「未完整发送」见 FR-008 澄清标记）。
- **ping 命令缺失** → 返回失败；**ping 超时** → 返回失败并记 loss=100%；**全丢包** → avg 为无穷大。
- **日志父目录不存在 / 写入失败** → 返回失败，不写文件。
- **环境变量未注入（独立使用场景）** → 回退内置默认值。

## 功能需求（必填）

- **FR-001**: traffic_send 必须能向 allowlist 内目标发送 UDP 流量，支持目标端口、发送时长、速率、报文大小、并发流数与间隔抖动参数（抖动幅度 0 至上限可配置）。
- **FR-002**: 每个发送流量或探测工具在执行前必须校验目标：IP 格式合法、位于 allowlist、非广播、非组播；任一不满足即拒绝执行并返回明确错误。
- **FR-003**: 系统必须禁止源 IP 伪造：源 IP 参数只允许为空，提供任何值即拒绝执行。
- **FR-004**: 数值参数必须按上限钳制：速率 ≤20000 pps、时长 ≤20 秒、报文大小 ≤1024 字节、并发流 ≤100、抖动 ≤20 ms；超限时按上限执行，返回结果必须携带钳制后的实际参数。[需要澄清 1/3：钳制感知——结果是否应同时返回「原请求值」并标注「已钳制」，让 Agent 明确知道自己请求超限（当前只返回钳制后的值，Agent 可能误以为目标值已生效而继续加大）。]
- **FR-005**: 非正数的速率、时长、报文大小、并发流以及负抖动必须被拒绝并返回错误（而非钳制）。
- **FR-006**: 目标端口必须为 1–65535 的整数，越界即拒绝。
- **FR-007**: 多流发送时，每条流必须使用互不相同的源端口，报文必须在各流之间轮转分配。
- **FR-008**: 发送结果必须包含：实际生效的参数、发送报文总数、每条流的发送数、实际耗时、实际速率，以及所采用的发送通道。[需要澄清 3/3：中断截断标注——发送被中断（如 Ctrl-C）时当前静默停止并返回已发送统计；是否应在结果中标注「未按计划完整发送」，避免 Agent 把截断结果当作完整攻击窗口观测。]
- **FR-009**: traffic_send 与 mixed_traffic_send 在发送前必须经过 HITL 审批；审批拒绝时不得发送任何报文，并向调用方返回拒绝结果。
- **FR-010**: mixed_traffic_send 必须接受 JSON 流量规格：流数量 1–100，每条流含唯一标识、协议栈、字段与百分比；协议仅限白名单内的类型；规格文本长度受限（≤10000 字符）。
- **FR-011**: 规格内声明的目标 IP 必须被忽略，实际发送目标一律为工具参数指定的目标 IP，防止通过规格绕过 allowlist。
- **FR-012**: 流百分比必须为 1–100 的整数且总和为 100；缺失的百分比必须被平均补齐；无法补齐（显式百分比之和已 ≥100）或总和不为 100 时拒绝整个规格。
- **FR-013**: 规格中的字段值必须经过危险模式扫描，检出注入特征时拒绝整个规格并说明原因。
- **FR-014**: 发送时必须按各流百分比加权随机选择流，并按流统计实际发送数量。[需要澄清 2/3：抖动口径一致性——当前 mixed_traffic_send 固定以最大抖动幅度（±20 ms）发送且不可配置，而 traffic_send 的抖动可在 0–20 ms 间配置；是否应统一为可配置，避免两种工具的流量形态不可比。]
- **FR-015**: ping_rtt 必须对 allowlist 目标执行单次探测，返回平均 RTT、丢包率、发送数与接收数；全部丢失时 RTT 记为无穷大；探测命令缺失或超时时返回失败结果。
- **FR-016**: log_result 必须把轮次号、参数、RTT、丢包以一行 JSON 追加写入指定日志文件，并附带 UTC 时间戳；日志文件所在目录不存在时返回失败且不创建文件。
- **FR-017**: 四个工具的默认参数必须在调用时从环境变量读取（由统一配置注入），未注入时回退到内置默认值；不得在工具内固化与配置冲突的默认值。
- **FR-018**: 工具对外说明（参数文档、Agent 可见的描述）中的上限必须与实际强制上限一致，不得残留过时的陈旧值（文档真实性）。
- **FR-019**: 发送型工具的结果必须附带攻击窗口内的 RTT 观测与对齐信息（观测窗口是否覆盖攻击窗口），其字段结构由 003-ping-monitor-rtt 规格定义。

### 关键实体（涉及数据时填写）

- **流量发送参数集**：目标 IP/端口、时长、速率、报文大小、流数、抖动；执行时以钳制后的实际值为准。
- **流量规格（traffic spec）**：描述混合流量的结构化输入；由若干「流」组成，每条流 = 唯一标识 + 协议栈 + 字段 + 百分比。
- **发送结果**：实际参数、总/分（流）发送计数、耗时、实际速率、发送通道，以及攻击窗口观测字段。
- **RTT 探测结果**：平均 RTT、丢包率、发送/接收计数（全丢包时 RTT 为无穷大）。
- **实验日志条目**：轮次号、参数、RTT、丢包与 UTC 时间戳，单行 JSON 追加存储。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 100% 的越限数值参数被钳制到上限执行（如 pps=999999 → 20000），返回值为钳制后的参数；安全违规（目标/端口/源伪造）100% 被拒绝且发送 0 报文。
- **SC-002**: 非 allowlist、广播、组播目标的调用 100% 被拒绝。
- **SC-003**: HITL 审批被拒绝的轮次发送报文数为 0。
- **SC-004**: 当并发流数为 N（1≤N≤100）时，发送结果覆盖 N 条流、各流源端口互不相同，且任意两条流发送数之差 ≤1（轮转分配）。
- **SC-005**: 非法混合规格（协议越白名单、流数越界、总百分比≠100、注入特征、超长文本、重复流标识）100% 被拒绝并给出具体原因；合法规格（含缺失百分比）100% 可执行且补齐后百分比总和为 100。
- **SC-006**: 大批量（≥10000 报文）混合发送时，各流实际占比与声明百分比的偏差 ≤5 个百分点。
- **SC-007**: ping_rtt 对可达的 allowlist 目标在 15 秒内返回结果；全丢包时 loss_pct=100 且 avg_rtt_ms 为无穷大；探测命令缺失时返回失败。
- **SC-008**: 每条日志为单行合法 JSON 且含 UTC 时间戳；追加写入不覆盖历史行；目录缺失时返回失败。
- **SC-009**: 工具对外说明所述上限与实际钳制上限 100% 一致（无陈旧值残留）。

## 假设

- 运行环境具备发送网络流量的能力，或可自动降级到无需特权通道。
- allowlist 的内容与维护由 008-security-config 规格统一管理，本规格只约束校验行为。
- 结果中的观测字段（rtt_during / attack_window / observation_window）结构与对齐语义由 003-ping-monitor-rtt 规格定义，本规格只要求附带。
- 已知 Agent 可见工具描述中存在陈旧上限值（200/10/512/50），本规格以源码常量与项目宪法为准，并由 FR-018 要求修复文档。
- 实验在已获授权向 allowlist 目标发送流量的网络内进行。
- 抖动钳制上限 20 ms 适用于单协议工具；混合工具的抖动口径按 FR-014 澄清结果统一。
