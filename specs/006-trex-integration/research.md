# 研究文档：TRex 集成与攻击目录探索

**特性目录**: `specs/006-trex-integration/` | **日期**: 2026-11-19

本文档记录阶段 0 研究结论：每个决策按「决策 / 理由 / 备选方案」格式，来源为 spec.md 的待澄清问题与宪法核对中发现的技术选择。

## 澄清项采纳（Lead 指定推荐默认）

### D1（澄清 006-1）：接受 HITL 为唯一硬边界（静态 IP 筛查可被混淆）

- **决策**: 维持现状——静态 IP 筛查定位为 best-effort 辅助检查（字符串拼接、域名、整数/十六进制形式可绕过），不追加运行时网络 ACL 或复杂检测；HITL 审批是唯一硬安全边界，审批材料展示脚本内容预览并如实声明「此脚本将以本机当前用户完整权限执行任意 Python（无执行沙箱）」（G3 补充「静态筛查可被混淆绕过」提示）。
- **理由**: 混淆检测不可穷尽（宁可声明边界也不制造虚假安全感）；审批材料展示脚本本体 + 完整权限警告，操作员审阅是最终且可靠的防线；追加运行时隔离（容器/沙箱）复杂度远超本特性范围。
- **备选方案**: ①运行时网络 ACL/沙箱强化（否决：复杂度与依赖面大幅增加，且仍有逃逸面）；②对含域名/动态获取地址的脚本一律拒绝（否决：误伤合法脚本，如经环境变量读地址）。

### D2（澄清 006-2）：探索预算耗尽未达 catalog_target → 非 0 退出码失败

- **决策**: 探索结束后由 `main.py` 对 `trex_scripts/cat_*.py` 逐一做语法检查并计数：≥catalog_target → 进程退出码 0；未达标 → 仍按 FR-021 输出并落盘已完成总结，但进程以非 0 退出码（1）结束。统计口径与工具一致（仅解析语法，不执行脚本）。
- **理由**: 自动化编排（CI、定时任务、批量评估）需要机器可读的成败信号；总结落盘保留人工审查价值，两者不冲突。与 FR-021「输出已完成总结后结束」兼容——「结束」不崩溃、不悬挂，退出码表达达标与否。
- **备选方案**: ①维持恒 0 退出码（否决：无法区分达标/未达标，SC 不可自动验证）；②未达标不落盘（否决：违反 FR-018/FR-021，丢失已生成资产）；③中途强制中断 Agent 循环（否决：打断 LangGraph 循环复杂且损失部分成果，事后校验即可）。

### D3（澄清 006-3）：cat_ 脚本采用显式清理参数（不自动清空）

- **决策**: 新增 CLI 参数 `--clean-scripts`（bool，默认 False，仅探索模式生效）：启动时若设置，删除 `trex_scripts/cat_*.py`（**仅 cat_ 前缀**，绝不动其他文件），并在启动横幅打印清理行为。命名与 `--catalog-target`、`--explore-direction` 同族。
- **理由**: 不自动清空——操作员可能有意保留历次脚本资产；显式参数让清理成为有意行为且可观测。只删 cat_ 前缀把爆炸半径限制在本模式产物内。
- **备选方案**: ①每次探索自动清空（否决：可能误删人工保留资产，且不可预期）；②不提供清理（否决：脚本持续累积，影响后续 live 执行误选风险）；③清理范围扩到整个目录（否决：目录中可能存在非探索脚本）。

## 宪法核对中的补充决策

### D4（新增）：「未达标不得提前结束」采用双层保障，不引入运行中断入

- **决策**: FR-016「未达标不得提前结束」的第一层保障是提示词硬性约束（`trex_catalog_prompt.j2` 停止条件），第二层保障是 G1 的事后退出码校验；不引入运行中强制干预（如达标前禁止 Agent 输出最终总结）。
- **理由**: 运行中断入（拦截 Agent 输出/中断循环）实现复杂且收益有限；事后退出码已把「未达标」变成可检测的失败状态，且保留已完成总结的资产价值。
- **备选方案**: ①运行中强制（否决：复杂、易与 LangGraph interrupt 机制冲突）；②仅靠提示词（否决：无法机器验证，D2 已决定退出码机制）。

### D5（现状确认，无改动）：工具层与探索模式主体

- **决策**: 维持现状——`write_python_file`（bare `*.py` 校验、保留名拒绝、100k 字符/2000 行上限、仅解析语法检查、语法错误仍落盘）与 `run_python_file`（存在性 → 语法 → 静态 IP 筛查 → target_ip allowlist → HITL → 超时 (0,300]s → 结果透传）均已实现且有 20+ 单测；探索模式工具集限制（graph.py mode="catalog" → 仅 TREX_TOOLS + 强制 dry-run）、提示词协议（规划→生成→校验重试→总结）、摘要落盘（时间戳防覆盖）均已实现。
- **理由**: 回溯式计划的事实基础——缺口只存在于 CLI 编排层（G1/G2/G3）。
- **备选方案**: 无（现状即契约，见 contracts/）。

## 澄清决议补录（Lead 定调，2026-11-19）

### D6（澄清·catalog_target 边界取值）：采纳候选 A —— 解析时拒绝 <1

- **决策**: 采纳候选 A。`main.py` 解析 `--catalog-target` 时校验：<1（0 或负数）立即报错并以非 0 退出码退出，与 FR 中「互斥参数启动报错」口径一致；校验并入差距 G1 一并实施与测试。
- **理由**: 0/负数无业务语义，静默接受会导致达标校验立即通过或永不通过，破坏 D2 退出码信号的可靠性；解析期拒绝成本最低、可测性最好。
- **备选方案**: ①B 维持现状并文档声明（否决：把无意义输入变成隐性行为陷阱，Lead 未采纳）；②钳制到 1（否决：静默改写输入，违背可观测驱动）。
