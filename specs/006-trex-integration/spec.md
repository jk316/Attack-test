# 功能规格：TRex 集成与攻击目录探索

**特性目录**: `specs/006-trex-integration/`

**创建日期**: 2026-11-19

**状态**: 草案

**输入**: 用户描述："为闭环网络实验 Agent 集成 Cisco TRex 客户端能力：暴露 2 个 TRex 工具——`write_python_file`（把脚本写入 trex_scripts/ 沙箱目录并做仅解析的语法检查）与 `run_python_file`（子进程执行，带 allowlist/HITL/超时门控）；默认 dry-run（只写脚本+语法检查、零流量），`--trex-live` 才真正执行；`--trex-explore` 为攻击目录探索模式——工具集仅含这 2 个 TRex 工具、强制 dry-run（零流量零 HITL）、生成至少 10 个带中文注释的 `cat_` 前缀攻击脚本、目录摘要写入 output/trex_attack_catalog_<时间戳>.md，支持 `--catalog-target` 与 `--explore-direction` 参数；`--trex-explore` 与 `--trex-live` 互斥。"

## 用户场景与测试（必填）

### 用户故事 1 - 受门控的 TRex 脚本写入与执行（优先级：P1）

实验代理用脚本生成与执行两个工具驱动 TRex 服务器：`write_python_file` 把生成的客户端脚本写入专用脚本沙箱目录并返回仅解析（不执行）的语法检查结论；`run_python_file` 按「文件存在性 → 语法检查 → 静态 IP 筛查 → 目标 IP allowlist → 人工审批 → 超时执行」的门控链真正运行脚本，把返回码、输出与耗时带回给 Agent。

**为什么是这个优先级**: TRex 集成（有状态 L4–L7 流量）的全部价值都经由这两个工具落地；而「写脚本≠执行脚本」的两段式设计与完整门控链是宪法「安全优先」在任意代码执行场景下的直接体现，是本功能的最小可交付闭环。

**独立测试方式**: 不依赖探索模式即可完整测试：断言 `write_python_file` 只落盘到沙箱目录且返回语法结论；dry-run 下断言 `run_python_file` 零执行；live 下用无害测试脚本断言审批流、allowlist、超时与返回码透传。验证通过即带来「受门控的 TRex 客户端生成与执行」完整价值。

**验收场景**:

1. **给定** 一个纯文件名（如 `cat_udp_flood.py`）与合法脚本内容，**当** Agent 调用脚本写入工具，**那么** 文件被写入专用脚本沙箱目录并返回路径与语法检查结论（含错误行号，如有）。
2. **给定** 文件名含路径（如 `../evil.py`）或非 `.py` 后缀，**当** Agent 调用脚本写入工具，**那么** 系统拒绝写入并返回明确错误。
3. **给定** 默认 dry-run 且脚本已写入，**当** Agent 调用脚本运行工具，**那么** 系统只做存在性与语法检查、报告检测到的 IP，绝不执行脚本、零流量。
4. **给定** 已启用 `--trex-live`、脚本语法正确、IP 字面量均在白名单且操作员批准，**当** Agent 调用脚本运行工具，**那么** 系统以受超时约束的子进程执行脚本并返回返回码、输出与耗时。
5. **给定** 脚本含非白名单 IP 字面量，**当** 在 live 模式调用脚本运行工具，**那么** 系统拒绝执行并列出可疑 IP，提示加入白名单或修改代码。

### 用户故事 2 - 默认 dry-run 与模式互斥（优先级：P2）

TRex 工具默认处于 dry-run（只写脚本与语法检查，零流量零审批），操作员显式传入 `--trex-live` 才允许真正执行脚本；若同时给出 `--trex-explore` 与 `--trex-live`，程序必须报错并拒绝启动，保证探索模式在结构上不可能发流量。

**为什么是这个优先级**: 本故事把「默认零流量」与「探索模式绝不发流量」固化为启动层面的不变量，是宪法「安全优先」的兜底保障，也决定了三种模式（dry-run/live/explore）的边界清晰度。它排在 P1 之后，因为 P1 的工具门控是基础，本故事在其上约束全局模式。

**独立测试方式**: 单独验证启动行为即可：不带任何 TRex 开关断言为 dry-run（零流量零审批）；带 `--trex-live` 断言执行路径开放；同时带两个开关断言启动被拒绝且退出码非 0。无需依赖具体脚本内容。

**验收场景**:

1. **给定** 启动命令未含任何 TRex 开关，**当** Agent 使用 TRex 工具，**那么** 全程零流量、零审批，结果模式标记为 dry-run。
2. **给定** 启动命令含 `--trex-live`，**当** Agent 调用脚本运行工具且门控全部通过，**那么** 脚本被真实执行。
3. **给定** 启动命令同时含 `--trex-explore` 与 `--trex-live`，**当** 程序启动，**那么** 程序立即报错拒绝启动，不进入任何 Agent 循环。

### 用户故事 3 - 攻击目录探索模式（优先级：P3）

操作员运行 `--trex-explore`：Agent 只拿到 2 个 TRex 工具且被强制 dry-run，按「先规划分类枚举 → 逐类生成 → 语法校验（失败修复重试）→ 总结」的协议生成至少 10 个（可经 `--catalog-target` 调整）文件名以 `cat_` 开头的攻击脚本，每个脚本头部含结构化中文注释块；结束时输出攻击目录摘要表格与能力边界总结，并持久化到 `output/trex_attack_catalog_<时间戳>.md`；`--explore-direction` 可注入自由文本以定向探索。

**为什么是这个优先级**: 探索模式是「零风险能力边界测绘」——它把 Agent 的代码生成能力用于生产可复用攻击资产而非发送流量，价值独立但优先级低于「可用的执行链路」，且依赖 P1 的写入/语法检查工具，因此排 P3。

**独立测试方式**: 单独运行 `--trex-explore` 即可完整验证：断言工具集仅 2 个 TRex 工具、全程零流量零审批、产出 ≥N 个语法通过的 `cat_*.py`、100% 脚本含中文注释块、摘要文件落盘且多次运行互不覆盖。

**验收场景**:

1. **给定** 运行 `--trex-explore`（默认目标 10），**当** Agent 完成探索，**那么** 沙箱目录中存在 ≥10 个 `cat_` 前缀且语法校验通过的脚本，每个脚本头部含「攻击名称/类别/机制/关键参数/预期效果」中文注释块。
2. **给定** 某个生成的脚本语法校验失败，**当** Agent 按协议处理，**那么** Agent 修复后重新校验，直到通过后才计入达标数量。
3. **给定** 运行 `--trex-explore --explore-direction "重点探索DNS放大攻击和TCP SYN洪水"`，**当** Agent 规划阶段，**那么** 该方向被优先覆盖，且总结中说明该方向的覆盖情况。
4. **给定** 探索完成，**当** 会话结束，**那么** 目录摘要表格与能力边界总结写入 `output/trex_attack_catalog_<时间戳>.md`，时间戳确保多次运行互不覆盖。
5. **给定** 探索全程，**当** 观察流量与审批事件，**那么** 全程零流量、零审批（工具集仅 2 个且强制 dry-run）。

## 边界情况

- **文件名非法**（含目录、非 `.py` 后缀、系统保留名如 Windows 的 CON/PRN）：写入工具拒绝并返回明确错误。
- **脚本不存在即运行**：返回「脚本不存在，请先写入」错误。
- **脚本语法错误**：dry-run 下如实报告错误行号；live 下拒绝执行。文件仍保留落盘供人工检查修复。
- **脚本规模超限**（超过 100000 字符或 2000 行）：写入拒绝。
- **静态 IP 筛查被混淆绕过**（字符串拼接、域名、十六进制等）：筛查是尽力而为而非硬边界，实际兜底是人工审批，见「待澄清问题」1。
- **TRex 服务器不可达**：脚本执行以非 0 返回码结束，错误输出随结果返回，Agent 可据此判断。
- **执行超时**：按配置超时（默认 30 秒、上限 300 秒）强制终止并返回超时结果。
- **探索模式预算耗尽但未达 catalog_target**：必须输出已完成部分的总结后结束（是否判失败见「待澄清问题」2）。
- **explore-direction 为空**：执行通用多维度枚举（不报错）。
- **多次探索运行**：`cat_` 前缀避免覆盖已有脚本，但旧脚本会累积在沙箱目录，见「待澄清问题」3。

## 功能需求（必填）

- **FR-001**: 系统必须提供脚本写入工具，仅接受不含目录的纯 `.py` 文件名，并把脚本写入专用脚本沙箱目录；路径穿越、非 `.py` 后缀与系统保留名必须拒绝。
- **FR-002**: 系统必须限制脚本规模（不超过 100000 字符、2000 行），超限请求必须拒绝。
- **FR-003**: 系统必须在脚本写入后执行仅解析（不执行）的语法检查，并在结果中返回语法检查结论与错误行号；语法错误的脚本仍须落盘以便人工检查修复。
- **FR-004**: 系统必须提供脚本运行工具，仅能运行已存在于专用脚本沙箱目录的脚本；脚本不存在时必须报错并提示先写入。
- **FR-005**: 系统必须默认处于 dry-run：脚本运行工具只做存在性与语法检查并报告检测到的 IP，绝不执行脚本、零流量；仅在操作员显式启用实发开关（`--trex-live`）后才允许执行。
- **FR-006**: 系统必须在实发前强制语法检查，存在语法错误的脚本必须拒绝执行。
- **FR-007**: 系统必须在实发前对脚本中的 IP 字面量做静态筛查：发现非白名单 IP 必须拒绝执行并列出可疑 IP；TRex 服务器自身地址与环回地址豁免。
- **FR-008**: 系统必须对脚本运行工具的可选目标 IP 参数执行 allowlist 校验，不合法必须拒绝。
- **FR-009**: 系统必须在实发执行前触发操作员人工审批，审批材料必须包含文件名、目标 IP、检测到的 IP 列表与脚本内容预览；操作员拒绝则零执行。
- **FR-010**: 系统必须为脚本执行设置超时约束（默认 30 秒、可配置、上限 300 秒）；超时必须强制终止并返回超时结果。
- **FR-011**: 系统必须在执行结果中返回返回码、标准输出与错误输出（经长度截断保护）、执行耗时与检测到的 IP；执行成功且提供了目标 IP 时必须附加 RTT 观测。
- **FR-012**: 系统必须在探索模式下只向 Agent 暴露这 2 个 TRex 工具并强制 dry-run，使该模式结构上不可能产生流量或触发审批。
- **FR-013**: 系统必须在探索模式下要求 Agent 先输出分类枚举规划，再逐类生成攻击脚本；脚本文件名必须以 `cat_` 开头。
- **FR-014**: 系统必须要求每个生成的攻击脚本头部包含结构化中文注释块，至少含「攻击名称 / 攻击类别 / 攻击机制 / 关键参数 / 预期效果」五个字段。
- **FR-015**: 系统必须要求 Agent 对每个生成的脚本执行语法校验，校验失败必须修复后重试，通过后才计入达标数量。
- **FR-016**: 系统必须要求探索模式生成并通过语法校验至少 N 个攻击脚本（默认 N=10，可经 `--catalog-target` 配置），未达标不得提前结束（预算耗尽除外）。
- **FR-017**: 系统必须要求在探索结束时输出攻击目录摘要——Markdown 表格（攻击名称 / 类别 / 机制 / 脚本文件 / 关键参数 / 预期效果）并附能力边界总结（覆盖与未覆盖的攻击维度）。
- **FR-018**: 系统必须把探索模式的目录摘要持久化到 `output/trex_attack_catalog_<时间戳>.md`，时间戳必须保证多次运行互不覆盖。
- **FR-019**: 系统必须支持 `--explore-direction` 参数注入自由文本探索方向，并让 Agent 在规划阶段优先覆盖该方向、在总结中说明其覆盖情况；该参数为空时执行通用枚举。
- **FR-020**: 系统必须保证 `--trex-explore` 与 `--trex-live` 互斥：同时提供时报错并拒绝启动。
- **FR-021**: 系统必须为探索模式设置总迭代预算；预算耗尽仍未达标时，Agent 必须输出已完成部分的总结后正常结束。
- **FR-022**: 系统必须在每次工具调用时读取主机、端口、脚本目录、超时与 dry-run 标志的最新配置（环境覆盖优先于配置文件），不得在模块加载时固化。

### 关键实体（涉及数据时填写）

- **TRex 脚本（Script）**: Agent 生成的客户端脚本；属性含文件名、源码、语法检查状态、检测到的 IP 列表、可疑（非白名单）IP 列表。
- **脚本沙箱目录（Script Sandbox）**: 脚本的唯一合法落盘位置；写入工具只允许写入该目录，运行工具只允许运行该目录内文件。
- **执行结果（Execution Result）**: 返回码、标准输出/错误（截断后）、耗时、超时标志、检测到的 IP、可选 RTT 观测。
- **攻击目录条目（Catalog Entry）**: 攻击名称、类别、机制、脚本文件、关键参数、预期效果；对应一个 `cat_*.py` 脚本。
- **目录摘要（Catalog Summary）**: 探索模式最终产物——目录表格与能力边界总结，持久化为 `output/trex_attack_catalog_<时间戳>.md`。
- **探索配置（Explore Config）**: 最少脚本数（catalog_target）、探索方向（explore_direction）、迭代预算（max_iters）。

- **SC-006**: 脚本执行超时时，系统在配置超时值 +2 秒内终止进程并返回超时结果。

## 假设

- 目标环境已获得合法授权，操作员对脚本执行负最终责任。
- 静态 IP 筛查是尽力而为的辅助检查而非硬安全边界；被混淆（字符串拼接、域名、整数形式）的 IP 由人工审批兜底。
- 生成的脚本以 Agent 进程的当前用户权限执行（无操作系统级沙箱），审批材料中已向操作员明示该风险。
- 目录摘要时间戳取本次运行启动时刻，同一秒内只会有一次运行。
- 探索模式产出脚本是面向未来执行的资产，本模式只校验语法、不做语义/可运行性验证。
- 本规格不覆盖 Web 控制台下的 TRex 交互差异，CLI 与 Web 共用同一工具实现。

## 待澄清问题

按影响排序：

1. **[需要澄清：静态 IP 筛查可被混淆绕过（尽力而为），是否接受「人工审批」作为唯一硬边界？]** 当前设计明确声明筛查非硬边界，依赖 HITL 兜底。影响：安全承诺口径与外部评审预期。（选项：A 接受现状——筛查为辅助、HITL 为硬边界——推荐；B 强化筛查（如运行时网络 ACL）后再宣称硬边界；C 对含任何域名/外部获取地址的脚本一律拒绝）
2. **[需要澄清：探索模式预算耗尽而未达 catalog_target 时应视为「正常结束」还是「失败」？]** 当前按「输出已完成总结后正常结束」处理，不区分达标与否。影响：验收口径、自动化编排对退出码的依赖。（选项：A 维持现状——正常结束并输出已完成总结；B 未达标时以非 0 退出码标记失败——推荐；C 未达标时自动追加一轮补足后才结束）
3. **[需要澄清：探索生成的 cat_ 脚本长期累积在 trex_scripts/，是否需要清理策略？]** 当前仅以 `cat_` 前缀避免覆盖已有脚本，多次运行会持续累积。影响：目录卫生与后续 live 执行的误选风险。（选项：A 维持现状——仅提示不清理；B 每次探索运行前清空 cat_ 脚本；C 提供显式清理参数由操作员决定）
