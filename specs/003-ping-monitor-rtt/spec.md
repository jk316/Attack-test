# 功能规格：Ping 监控与 RTT 观测

**特性目录**: `specs/003-ping-monitor-rtt/`

**创建日期**: 2026-11-19

**状态**: 草案

**输入**: 用户描述："为闭环网络实验 Agent 提供持续后台 ping 监控与对齐感知的 RTT 观测能力。高分辨率模式优先：每秒约 10 次探测、每秒输出一行摘要、每个摘要周期的发送/接收计数加权记为样本（fping -Q 风格）；不可用时自动回退到系统 ping 连续模式（Windows 连续 ping、Unix 连续 ping），跨语言解析丢包提示（英文 + 中文）。监控为进程级单例，样本存于线程安全有界缓冲；提供按时间戳采样查询 get_samples_since(t0)。每次攻击动作结束后构造对齐观测 build_rtt_observation：attack_window（开始/结束时刻 + 执行模式）、observation_window（首末样本时间 + covers_attack_window 布尔）、rtt_during（逐样本 + 聚合统计）。另有单次 ping RTT 测量与 allowlist 校验。宪法核心原则：可观测驱动——每个攻击动作必须有观测回馈，无观测回馈的动作不得作为决策依据。"

## 用户场景与测试（必填）

### 用户故事 1 - 持续后台监控：高分辨率探测与跨平台回退（优先级：P1）

操作员启动闭环实验后，Agent 需要对目标持续发送 ping 探测，为每一轮攻击提供实时 RTT 与丢包观测。系统在后台运行一个持续监控：在具备高分辨率探测工具的环境，采用「每秒约 10 次探测、每秒输出一行摘要」的模式，每个摘要周期按该周期真实的发送数/接收数加权记为一条样本；工具不可用或运行于 Windows 时，自动回退到操作系统自带的 ping 连续模式（Windows 与 Unix 各按平台方式运行），并把超时、目标不可达等提示识别为丢失——该识别同时支持英文与中文环境的提示文本。Agent 随时可以读取最近时间窗口的聚合统计：发送数、收到数、丢失率、平均/最小/最大 RTT、最新 RTT，以及当前使用的后端与目标 IP。

**为什么是这个优先级**: 项目宪法「可观测驱动」是核心原则——没有持续、可靠的 RTT 观测，闭环实验的一切调参决策都失去数据依据；持续监控是整个 Agent 的「感官」，是其余观测能力（观测对齐、单次测量）的数据源头，必须最先成立。仅交付本故事即可独立支撑「攻击 → 观测」的最小闭环。

**独立测试方式**: 在装有高分辨率探测工具的 Linux/macOS 环境，启动监控 5 秒后查询 1 秒窗口统计，验证每秒约 10 个探测被加权汇总、丢失率与构造的丢包一致、后端标注为高分辨率模式；再在无该工具的 Windows 环境重复启动，验证自动回退到系统 ping，且中文「请求超时」行被计为丢失。仅此一条故事即可获得可用的持续监控 MVP，无需依赖其他故事。

**验收场景**:

1. **给定** allowlist 内目标 IP 且高分辨率探测工具可用，**当** 操作员启动持续监控并等待 3 秒后查询 1 秒窗口统计，**那么** 返回发送数约为 10、收到数与丢失率为窗口内真实值、平均/最小/最大 RTT 为窗口内收到探测的加权统计、后端标注为高分辨率模式。
2. **给定** 无高分辨率工具的 Windows 环境与一个间歇丢包的目标，**当** 启动监控并等待数秒后查询统计，**那么** 系统自动使用系统 ping 连续模式，输出中出现中文「请求超时」的周期被计为丢失，丢失率大于 0 且与真实丢失一致。
3. **给定** Unix 环境与一个间歇丢包的目标，**当** 启动监控并等待数秒后查询统计，**那么** 系统使用 Unix 连续 ping 模式，输出中 "Request timed out" / 目标不可达等提示行被计为丢失，丢失率大于 0。

### 用户故事 2 - 攻击期间的 RTT 观测对齐（优先级：P2）

Agent 每执行一次流量攻击，工具结果必须附带该次攻击期间的 RTT 观测，并显式回答「观测是否真正覆盖了攻击窗口」。系统以攻击开始时刻 t0 为基准取出其后样本，构造三部分：attack_window（攻击开始/结束时刻、时长、执行模式）、observation_window（样本数、首末样本时刻、covers_attack_window 布尔与说明）、rtt_during（逐样本列表 + 平均/最小/最大 RTT、丢失率、收发总数）。当监控未运行、窗口内无样本、探测全部丢失、或攻击窗口短于有意义阈值（1 秒）时，必须判定「未覆盖」并写明原因，禁止把不可信数据当作有效测量；判定为「覆盖」的观测还要在说明中给出收发与丢失概况，丢失严重时提示这本身可能就是攻击效果信号。

**为什么是这个优先级**: 宪法「可观测驱动」要求每个攻击动作必须有观测回馈、无观测回馈的动作不得作为决策依据；covers_attack_window 是防止 LLM 用「错位数据」（攻击前/后的样本、dry-run 未发流的瞬时样本）做决策的关键护栏。它建立在 P1 的样本流之上，是对 P1 数据的「可信度封装」，因此排在 P1 之后、先于补充性的单次测量。

**独立测试方式**: 用已知时序的样本集合与攻击窗口组合（正常覆盖、窗口外样本、全丢失、空样本、窗口过短五类）调用观测构造，逐一核对 covers_attack_window、说明文本与 rtt_during 取值；再在真实攻击工具（如 UDP 流量发送）执行一次后检查返回结果中三个字段齐全且时间点合理。仅此故事即可获得「每轮攻击有可信观测」的增量价值。

**验收场景**:

1. **给定** 监控运行中且攻击窗口时长 ≥1 秒、窗口内存在成功探测样本，**当** 攻击结束后构造观测，**那么** rtt_during 包含逐样本列表与平均/最小/最大 RTT、丢失率、收发总数，observation_window.covers_attack_window 为 true，首/末样本时间落在攻击窗口时间范围内。
2. **给定** 监控未运行，**当** 攻击结束后构造观测，**那么** rtt_during 为空、covers_attack_window 为 false，说明文本明确提示「先启动监控，本结果不可用于规划」。
3. **给定** 攻击窗口过短（如 dry-run 未发流、时长为 0 未等待），**当** 构造观测，**那么** covers_attack_window 为 false 且说明写明窗口过短的原因，即使窗口内存在少量样本也不视为覆盖。
4. **给定** 窗口内所有探测均丢失，**当** 构造观测，**那么** rtt_during 为空或明确无值，说明写明全部丢失与丢失率 100%，不产生 0 毫秒的假 RTT 数据。

### 用户故事 3 - 单次 ping RTT 测量与安全校验（优先级：P3）

Agent 在没有后台监控时也能对目标做一次快速 RTT 测量（例如实验前的基线测量、监控不可用时的抽查）。系统对 allowlist 内的目标执行有限次数探测，解析英文与中文平台的输出，返回平均 RTT、丢失率、收发计数与原始输出；目标不在 allowlist、为广播/组播或格式非法时直接拒绝且不发出探测。全部丢失时 RTT 明确标识为不可用（如无穷大），不得记为 0 毫秒；探测命令缺失、子进程超时等失败场景返回带错误信息的结果而不是让实验崩溃。

**为什么是这个优先级**: 单次测量是后台监控的补充能力（基线、抽查、替代测量），价值真实但不断环——P1 已提供持续观测、P2 已提供攻击观测封装；它与监控共用同一套 allowlist 安全校验，是该校验在「按需测量」场景的落地。排在 P3 合理。

**独立测试方式**: 对 allowlist 内 IP 调用单次测量，验证返回平均 RTT、丢失率与收发计数；对非 allowlist、广播（x.x.x.255）、组播、非法格式的 IP 分别调用，验证全部被拒绝且不产生探测流量；构造全部丢失与超时的输出，验证 RTT 标识为不可用、丢失率 100%。仅此故事即可获得「带安全校验的单次测量工具」MVP。

**验收场景**:

1. **给定** allowlist 内可达目标，**当** 请求 4 次探测的单次测量，**那么** 返回成功结果：平均 RTT、丢失率、收发计数与原始输出，且与平台输出语言无关地可解析。
2. **给定** 不在 allowlist 的目标 IP（或广播/组播/非法格式），**当** 请求单次测量，**那么** 被拒绝并返回明确错误，不发送任何探测包。
3. **给定** 目标全部丢失（或测量超时），**当** 解析测量结果，**那么** 平均 RTT 标识为不可用（无穷大）、丢失率为 100%，成功标志与错误信息一致。

## 边界情况

- 目标 IP 不在 allowlist / 格式非法 / 广播 / 组播：监控启动与单次测量均必须拒绝并给出明确错误，不产生探测流量。
- 高分辨率探测工具不可用（Windows 或未安装）：自动回退到系统 ping 连续模式；连系统 ping 也不存在时，明确报错而不是静默失败。
- 监控运行中再次启动（更换目标）：先停止旧监控，再用新目标启动，全程仍是同一个进程级实例。
- 目标完全无响应：高分辨率模式摘要显示全部丢失（0 收到）时 RTT 记为无数据而非 0 毫秒；系统 ping 的超时行计入丢失。
- 攻击窗口过短（<1 秒，如 dry-run、时长为 0 未等待）：观测判定为未覆盖并说明原因。
- 监控未运行即构造攻击观测：返回未覆盖与提示，不抛异常。
- 样本缓冲写满：按容量上限淘汰最旧样本，内存占用有界。
- 探测子进程输出出现无法解析的行：跳过该行并限量记录日志，监控继续运行。
- 单次测量子进程超时 / 命令缺失：返回带错误信息的失败结果，不抛未捕获异常。
- 停止监控时探测进程已退出或读取任务已结束：停止操作安全且幂等，可重复调用。

## 功能需求（必填）

- **FR-001**: 系统必须在实验期间对指定目标持续发送 ping 探测，并采集每次探测的结果（RTT 与丢失）。
- **FR-002**: 系统必须在启动监控或单次测量前校验目标 IP：格式合法、非广播、非组播且位于 allowlist 白名单内；任一不满足即拒绝执行并给出明确错误。
- **FR-003**: 当高分辨率探测工具可用时，系统必须优先采用「约每秒 10 次探测、每秒输出一行摘要」的模式，并把每个摘要周期记录为一条样本，样本的发送数/接收数取该周期的真实计数（加权口径）。
- **FR-004**: 高分辨率探测工具不可用时，系统必须自动回退到操作系统自带的 ping 连续模式，并根据运行平台选用对应的运行方式，不得依赖写死的单一平台命令。
- **FR-005**: 回退模式下，系统必须解析每次应答的 RTT，并把超时、目标不可达等输出行识别为丢失探测；该识别必须同时支持英文与中文环境的提示文本。
- **FR-006**: 系统必须以线程安全的方式保存样本，允许后台写入与任意时刻的查询并发进行；样本容量必须有上限，超出时淘汰最旧样本，保证长期运行内存不无限增长。
- **FR-007**: 系统必须提供全局唯一的监控访问入口：进程内任意调用方获取到的都是同一实例，重复调用不得创建第二份后台监控。
- **FR-008**: 以新目标启动监控前必须先停止上一轮监控；系统必须支持在任意时刻停止监控——终止探测进程、结束读取任务并清除目标状态。
- **FR-009**: 系统必须支持查询最近时间窗口的聚合统计：发送数、收到数、丢失率、平均/最小/最大 RTT、最新 RTT，并标注当前目标与所用后端；监控未运行或窗口内无数据时必须返回明确的无数据状态而非报错。
- **FR-010**: 系统必须支持按时刻查询样本：返回指定时刻之后的所有探测结果（时间戳、RTT、发送数、接收数），按时间先后排列；丢失探测的 RTT 用空值表示。
- **FR-011**: 系统必须为每次流量攻击构造观测结果，包含：攻击窗口（开始/结束时刻、时长、执行模式）、观测窗口（样本数、首末样本时刻、是否覆盖攻击窗口、说明）与攻击期间逐样本 RTT 列表及聚合统计（平均/最小/最大 RTT、丢失率、收发总数）。
- **FR-012**: 监控未运行、窗口内无样本、探测全部丢失或攻击窗口短于有意义阈值（1 秒）时，系统必须将「是否覆盖攻击窗口」判定为否并在说明中写明原因；被判定为未覆盖的观测不得呈现为可信测量。
- **FR-013**: 丢失率必须按「1 − 收到数/发送数」统一计算；RTT 聚合只统计收到的探测，对多探测汇总样本按其收到数加权，保证高分辨率与回退两种模式的统计口径一致。
- **FR-014**: 系统必须支持对 allowlist 内目标的单次 RTT 测量（有限探测次数），返回平均 RTT、丢失率、收发计数与原始输出；全部丢失时 RTT 必须标识为不可用（如无穷大），不得记为 0。
- **FR-015**: 单次测量与监控在探测命令缺失、子进程超时等失败场景下，必须返回带明确错误信息的结果，不得以未捕获异常中断实验。
- **FR-016**: 实验进程正常结束时必须停止监控并回收探测进程与读取任务，不得遗留孤儿探测进程。

### 关键实体（涉及数据时填写）

- **监控样本**: 一个探测结果或高分辨率模式的一个摘要周期：采集时刻、RTT（丢失时为空）、发送数、接收数。
- **监控实例**: 全局唯一的后台监控器：当前目标 IP、运行状态、所用后端、有界样本缓冲；只通过唯一入口访问。
- **攻击窗口**: 一次攻击动作的时间范围：开始时刻、结束时刻、时长、执行模式。
- **观测窗口**: 攻击窗口对应的样本覆盖情况：样本数、首/末样本时刻、是否覆盖攻击窗口、说明文本。
- **攻击期间观测（rtt_during）**: 攻击窗口内逐样本列表与聚合统计：平均/最小/最大 RTT、丢失率、收发总数。
- **单次测量结果**: 一次有限探测的测量结果：成功标志、平均 RTT、丢失率、收发计数、原始输出、错误信息。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 高分辨率模式下，系统每秒发起 10 次探测（允许 ±1 次抖动），每个 1 秒摘要周期都形成一条样本；连续运行 60 秒产生的汇总样本数不少于 55 条。
- **SC-002**: 在无高分辨率工具的环境（Windows 或未安装该工具），系统 100% 自动回退到系统 ping 并持续产出样本；英文与中文的丢包提示文本均被正确计入丢失率（以覆盖两类文本的测试集验证，识别正确率 100%）。
- **SC-003**: 对已知样本时序与攻击窗口的组合（未运行、无样本、全丢失、窗口过短、正常覆盖共 5 类），covers_attack_window 与说明文本的判定 100% 符合预期。
- **SC-004**: 监控运行期间，10 个并发线程同时执行采样/统计查询共 1000 次，无异常抛出，且返回的样本数与串行查询结果一致。
- **SC-005**: 对非 allowlist、广播、组播、非法格式的目标，监控启动与单次测量的拒绝率为 100%，且拒绝时不产生任何探测流量。
- **SC-006**: 停止监控后 5 秒内探测进程退出；连续 20 次启动-停止循环后系统无残留探测进程。
- **SC-007**: 目标完全无响应时，聚合统计与单次测量的丢失率为 100%，RTT 标识为不可用（空值或无穷大），不出现 0 毫秒的假 RTT 数据。

## 假设

- 监控目标与攻击目标为同一 allowlist 内 IP；监控面向单一目标设计，更换目标即重启监控。
- Linux/macOS 实验环境默认安装高分辨率探测工具（fping）；未安装或 Windows 环境走系统 ping 回退。
- 攻击开始时刻 t0 与样本时间戳使用同一时钟源，可直接比较（无墙钟/单调钟混用问题）。
- 回退模式下探测间隔默认 1 秒，聚合查询窗口默认 5 秒。
- 目标主机持续开放 ICMP 响应；中间设备不阻断或限速 ICMP 探测。
- 监控与单次测量不产生攻击流量，无需 HITL 审批，仅执行 allowlist 等安全校验。
- 需要支持的提示文本语言环境为英文与简体中文两种。

## 需要澄清的问题（按影响排序）

1. **[需要澄清：是否支持同时监控多个目标 IP？]** 当前设计为单一目标（重新启动即更换目标）。若需多目标并行监控，将影响单例结构与样本、统计的口径。影响：功能范围（最大）。
2. **[需要澄清：探测节奏是否需要可配置？]** 高分辨率模式的探测节奏（10 探针/秒）与回退模式的探测间隔（默认 1 秒）当前为内置默认；宪法要求「配置单一来源」，是否需要将这些节奏放入统一配置文件由实验按需调整。影响：配置面与实验灵活性。
3. **[需要澄清：样本缓冲上限是否需要随实验时长调整？]** 当前上限约 4000 条（高分辨率模式约 66 分钟数据），已覆盖最长单轮实验（含硬件模式最长 60 秒等待），但更长的连续实验可能淘汰旧样本；是否按实验规模动态配置。影响：数据保留与内存权衡。
