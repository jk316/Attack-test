# 功能规格：Pktgen-DPDK 硬件集成

**特性目录**: `specs/005-pktgen-integration/`

**创建日期**: 2026-11-19

**状态**: 草案

**输入**: 用户描述："为闭环网络实验 Agent 集成 Pktgen-DPDK 硬件发包能力：暴露 9 个 Pktgen 工具（udp/tcp/icmp/arp 泛洪、范围扫描、报文序列、PCAP 回放、统计监控、停止复位），经 vendored 编译器将技能定义编译为硬件执行脚本并通过 TCP 控制通道（默认端口 22022）下发；默认 dry-run（只编译不发包），`--pktgen-live` 才真正发包；攻击期间同步等待（时长封顶 60 秒）并采集 RTT 观测；`packet_sequence` 自动把 LLM 臆造的 MAC 替换为 topology.yaml 的真实 `dst_mac`；强制 rate≤100%、攻击时长≤60000ms 与 allowlist/HITL 门控矩阵（arp_flood 与 pcap_replay 免 allowlist，stats_monitor 与 stop_and_reset 免 HITL）。"

## 用户场景与测试（必填）

### 用户故事 1 - 硬件线速泛洪四件套（优先级：P1）

实验代理需要以远超软件发包（Scapy）的吞吐量饱和目标链路，以观察目标在高负载下的 RTT 退化。它调用 UDP/TCP/ICMP/ARP 四类泛洪工具，指定速率百分比、时长与包参数；每次调用必须经过目标 IP allowlist 校验（ARP 除外）、实发模式人工审批与速率上限约束，保证高吞吐能力不与安全红线冲突。

**为什么是这个优先级**: 硬件级高吞吐泛洪是 Pktgen 集成区别于 Scapy 的核心价值——没有它，硬件集成本身不成立。同时本故事把宪法的「安全优先」门控（allowlist、HITL、参数上限）作为能力的一部分一并验证，构成可独立交付的最小闭环。

**独立测试方式**: 无需其他 Pktgen 工具即可完整测试：dry-run 下调用四个泛洪工具，断言全部返回编译产物路径且零网络流量；live 下使用模拟硬件端点，断言经 TCP 控制通道收到脚本、审批流触发、rate 越界被拒绝。该测试即带来「Agent 能以硬件吞吐发起四类 L3/L4/L2 泛洪」的完整价值。

**验收场景**:

1. **给定** 目标 IP 在 allowlist 内且 rate=50（默认 dry-run），**当** Agent 调用 UDP 泛洪工具，**那么** 系统仅完成编译并保存脚本产物，返回成功结果与产物路径，不连接硬件、不产生任何流量。
2. **给定** 已启用 `--pktgen-live` 且目标 IP 在 allowlist 内，**当** Agent 调用 TCP 泛洪工具且操作员批准审批，**那么** 系统将编译产物经 TCP 控制通道（默认端口 22022）下发至硬件并返回硬件响应。
3. **给定** 已启用 `--pktgen-live` 但操作员拒绝审批，**当** Agent 调用 ICMP 泛洪工具，**那么** 系统不发送任何流量并返回「操作员拒绝」的失败结果。
4. **给定** Agent 传入 rate=150，**当** 调用任意泛洪工具，**那么** 系统拒绝该请求并返回明确的参数错误，不下发硬件。
5. **给定** 目标 IP 不在 allowlist 内或为空，**当** Agent 调用 UDP/TCP/ICMP 泛洪工具，**那么** 系统在发送前拒绝并返回明确错误。

### 用户故事 2 - 默认安全模式与 RTT 观测闭环（优先级：P2）

实验代理默认在 dry-run 模式下工作（只编译、零流量），只有操作员显式传入 `--pktgen-live` 才真正发包；实发期间系统同步等待攻击窗口结束（等待时长封顶 60 秒），并在每次攻击后把后台 ping 监控的 RTT 采样附到工具结果中，标明攻击窗口与观测窗口是否重叠，让 Agent 依据实测数据做参数决策。

**为什么是这个优先级**: 本故事落实宪法「安全优先」（默认零流量）与「可观测驱动」（每次攻击必有 RTT 观测回馈）两大原则，是实验闭环可靠性的前提；没有它，Agent 会在数据缺失时做出无效优化。它排在 P1 之后，因为泛洪能力本身是前置条件，而本故事可以在泛洪 MVP 之上增量交付。

**独立测试方式**: 单独运行即可验证：默认启动（不带 `--pktgen-live`）断言零连接、零流量、结果模式为 dry-run；live 下用模拟硬件断言等待时长等于 min(duration, 60000) 毫秒，且结果包含 `rtt_during`、`attack_window`、`observation_window` 与覆盖标志。验证通过即证明「安全默认 + 观测闭环」成立。

**验收场景**:

1. **给定** 启动命令未含 `--pktgen-live`，**当** Agent 调用任意泛洪工具，**那么** 系统只编译并保存脚本、不连接硬件，结果中模式标记为 dry-run 且无流量产生。
2. **给定** 已启用 `--pktgen-live`、攻击时长 duration=5000ms 且批准通过，**当** 调用 UDP 泛洪工具，**那么** 系统在实发后同步等待约 5 秒，返回结果包含覆盖该攻击窗口的 RTT 观测与覆盖标志。
3. **给定** 攻击时长 duration=120000ms（超过上限），**当** 调用泛洪工具，**那么** 系统将同步等待封顶为 60 秒，并如实反映实际等待时长。
4. **给定** ping 监控未启动，**当** 执行攻击，**那么** 结果仍正常返回且观测字段以空值/覆盖标志为假的形式呈现，Agent 能据此判定观测不可用。

### 用户故事 3 - 高级流量构造与运维工具（优先级：P3）

实验代理需要更丰富的流量维度与实验卫生：`range_scan` 在硬件层逐包扫描参数区间、`packet_sequence` 按序循环发送最多 16 个完整报文模板（LLM 臆造的 MAC 自动替换为拓扑配置的真实 `dst_mac`）、`pcap_replay` 回放 Pktgen 主机上的 PCAP；同时用 `stats_monitor` 轮询端口统计、用 `stop_and_reset` 随时安全停止全部流量并复位端口，二者不产生流量、免人工审批、随时可调用。

**为什么是这个优先级**: 本故事扩展攻击维度（参数扫描、序列构造、真实流量回放）并补齐实验安全收尾（监控与止损）。它们不阻塞前两个故事的交付价值，且部分能力（扫描、回放）依赖前两个故事的编译下发链路，因此排在 P3。

**独立测试方式**: 逐工具独立验证：调用 `packet_sequence` 断言伪造 MAC 被替换为拓扑真实 `dst_mac` 且记录替换日志；调用 `range_scan` 断言扫描参数正确传递并编译；live 下调用 `pcap_replay`（免 allowlist、需审批）断言下发成功；任意时刻调用 `stats_monitor`/`stop_and_reset` 断言不触发审批且可执行。全部通过即带来「多维流量构造 + 安全止损」的完整价值。

**验收场景**:

1. **给定** 序列条目中 `eth_dst_addr` 缺失、为空或为 `00:00:00:00:00:01` 这类全 0/1 模式，**当** Agent 调用 `packet_sequence`，**那么** 系统把该条目替换为拓扑配置中的真实 `dst_mac` 并记录替换日志；真实 MAC 不被改动。
2. **给定** 序列 JSON 格式非法，**当** Agent 调用 `packet_sequence`，**那么** 系统返回明确的「序列 JSON 非法」错误，不进入编译。
3. **给定** 已启用 `--pktgen-live` 且操作员批准，**当** Agent 调用 `pcap_replay` 指定 Pktgen 主机上的 PCAP 文件，**那么** 系统下发回放指令且不要求目标 IP 白名单（PCAP 自带目标）。
4. **给定** 实验进行中（无论 dry-run 或 live），**当** Agent 调用 `stop_and_reset` 或 `stats_monitor`，**那么** 系统不触发人工审批、直接执行停止复位/轮询统计并返回结果。

## 边界情况

- **Pktgen 硬件不可达或连接超时**（默认 10 秒）：系统返回失败结果与可读错误摘要，明确提示「硬件不可达，可回落 Scapy 工具」，且不使 Agent 崩溃。
- **参数非法**（rate 越界、枚举取值非法、类型不符、必需参数缺失）：编译阶段拒绝并返回带参数名的错误，不下发硬件。
- **HITL 被拒绝**：不发送流量，返回「操作员拒绝」的失败结果。
- **需要目标 IP 的技能收到空 dst_ip**：在 allowlist 校验阶段拒绝，并提示必须提供白名单内目标 IP。
- **duration=0（表示永久发包）**：系统不做同步等待（不阻塞），攻击由硬件持续进行，依赖 `stop_and_reset` 终止——Agent 需知晓该语义。
- **duration 超过 60000ms**：同步等待封顶 60 秒；对「请求本身应拒绝还是钳制到上限」存在分歧，见「待澄清问题」1。
- **dry-run 模式下调用 stop/stats**：当前只编译不连接硬件，紧急停止在 dry-run 下不生效，见「待澄清问题」2。
- **PCAP 文件存在性**：文件必须位于 Pktgen 主机本地，Agent 侧无法预校验存在性，失败发生在硬件执行时并随响应返回。
- **多次运行产物**：编译产物以时间戳命名保存，多次运行互不覆盖，供事后审计。

## 功能需求（必填）

- **FR-001**: 系统必须向实验代理暴露 9 个 Pktgen 工具：UDP 泛洪、TCP 泛洪、ICMP 泛洪、ARP 泛洪、范围扫描、报文序列、PCAP 回放、统计监控、停止复位。
- **FR-002**: 系统必须在编译前校验全部参数的类型、取值范围与枚举取值；任一参数非法必须拒绝整个请求并返回包含参数名的明确错误，不得下发硬件。
- **FR-003**: 系统必须在实发模式下将编译产物经 TCP 控制通道（默认端口 22022）下发至硬件并返回硬件响应；连接失败时必须返回可读的失败结果（含「硬件不可达」类摘要），且不得导致 Agent 崩溃。
- **FR-004**: 系统必须默认处于 dry-run 模式：仅完成编译并保存脚本产物，不连接硬件、不产生任何流量；仅在操作员显式启用实发开关（`--pktgen-live`）后才允许下发。
- **FR-005**: 系统必须对需要目标 IP 的技能（UDP/TCP/ICMP 泛洪、范围扫描、报文序列）强制目标 IP 校验：目标 IP 缺失或不在 allowlist 内必须在发送前拒绝；ARP 泛洪（纯二层）与 PCAP 回放（使用 PCAP 自带目标）不要求目标 IP。
- **FR-006**: 系统必须在实发模式下对全部产生流量的技能（四类泛洪、范围扫描、报文序列、PCAP 回放，共 7 个）执行操作员人工审批；操作员拒绝时不得发送流量并返回拒绝结果；dry-run 模式不要求审批。
- **FR-007**: 系统必须保证统计监控与停止复位两个工具在任何模式下都免于人工审批且可随时调用——监控与止损操作不得被审批阻塞。
- **FR-008**: 系统必须将速率参数约束在 0–100（线速百分比）范围内；越界请求必须拒绝，不得下发。
- **FR-009**: 系统必须将攻击时长上限约束为 60000ms，且实发后为等待攻击完成而进行的同步等待时长必须封顶 60 秒。
- **FR-010**: 系统必须在实发攻击执行期间同步等待攻击窗口结束，使随后的 RTT 采样覆盖完整攻击窗口。
- **FR-011**: 系统必须在每次带目标 IP 的攻击执行后向结果附加 RTT 观测数据（`rtt_during`、`attack_window`、`observation_window` 及覆盖标志），并标注观测模式（dry-run/live），供 Agent 判断观测是否有效。
- **FR-012**: 系统必须为报文序列的每个序列条目检测目标 MAC 地址：缺失、为空或明显伪造（仅由 0/1 数字构成的全零/全一模式）时，替换为拓扑配置中声明的真实目标 MAC，并在日志与结果中记录替换行为；真实 MAC 不得被误替换。
- **FR-013**: 系统必须拒绝格式非法的报文序列输入并返回明确错误，不得进入编译。
- **FR-014**: 系统必须将每次编译产物保存为带时间戳的可审计脚本文件，并在工具结果中返回产物路径与脚本摘要（而非完整脚本内容）。
- **FR-015**: 系统必须为所有工具返回统一结构的结果：成功标志、技能名、执行模式（dry-run/live）、错误信息（如有）与可读摘要；失败时必须分类提示（参数错误 / 硬件不可达→建议回落 Scapy 工具）。
- **FR-016**: 系统必须禁止向广播/组播地址发送流量，并禁止源 IP 伪造。
- **FR-017**: 系统必须从统一配置源读取参数默认值，且每次调用时读取环境覆盖；不得在工具内硬编码默认值。
- **FR-018**: 系统必须以技能定义文件为 9 个技能语义的唯一来源，并保持其与上游定义同步，不得私自分叉语义。

### 关键实体（涉及数据时填写）

- **Pktgen 技能（Skill）**: 9 个技能定义；属性含名称、意图（流量生成/扫描/构造/监控/控制）、参数及默认值与约束、编译步骤。是编译的唯一语义来源。
- **编译产物（硬件执行脚本）**: 由技能定义与参数编译得到的可交付硬件执行的脚本；保存为时间戳命名的审计文件，工具结果仅引用其路径与摘要。
- **攻击请求（Attack Request）**: Agent 发起的一次工具调用；属性含技能名、参数、目标 IP（可选）、执行模式（dry-run/live）。
- **工具结果（Tool Result）**: 统一结构；属性含成功标志、技能名、模式、错误摘要、产物路径、硬件响应（live）、RTT 观测。
- **RTT 观测（RTT Observation）**: 攻击窗口起止、观测窗口起止、观测是否覆盖攻击窗口的标志、窗口内逐样本 RTT 与聚合统计。
- **拓扑配置（Topology）**: 硬件主机地址与控制端口、TX/RX 端口映射、真实目标 MAC；是地址类默认值的来源。

## 成功标准（必填）

### 可度量结果

- **SC-001**: 在 dry-run 模式下调用任意一个 Pktgen 工具，100% 不产生任何网络流量（以接口计数/抓包验证），且 100% 的调用返回编译产物路径。
- **SC-002**: 目标 IP 为空或不在 allowlist 内的请求，100% 在发送前被拒绝，且拒绝响应在 1 秒内返回。
- **SC-003**: 实发模式下未经操作员批准的流量请求，100% 不产生流量。
- **SC-004**: rate 超过 100% 的请求 100% 被拒绝；同步等待时长 100% 不超过 60 秒。
- **SC-005**: 100% 的带目标 IP 攻击调用返回 RTT 观测；实发模式下观测窗口覆盖攻击窗口的调用占比 ≥95%。
- **SC-006**: 伪造 MAC（全零/全一模式）的替换准确率为 100%，真实 MAC 误替换率为 0。
- **SC-007**: 硬件不可达时，Agent 在单次工具调用内即获得可读失败摘要并足以做出回落决策，无需人工排查。
- **SC-008**: 在正常负载下，dry-run 模式单次工具调用（不含攻击等待）端到端完成时间 ≤2 秒。

## 假设

- 目标环境已获得合法授权，操作员对硬件流量负最终责任。
- Pktgen 硬件主机与端口在拓扑配置中正确且可达；拓扑读取失败时回退到内置默认主机/端口/`dst_mac`。
- PCAP 文件由操作员预先放置到 Pktgen 主机本地，Agent 侧不校验其存在性。
- RTT 采样依赖后台 ping 监控已启动；未启动时观测字段以空值呈现且覆盖标志为假。
- 本规格不覆盖 Web 控制台对审批交互的呈现方式，复用现有审批机制即可。
- 攻击时长超过 60000ms 的请求当前按「同步等待封顶 60 秒」处理（是否改为拒绝见「待澄清问题」1）。

## 待澄清问题

按影响排序：

1. **[需要澄清：攻击时长超过 60000ms 的请求应拒绝还是钳制到上限？]** 宪法规定 Pktgen duration≤60000ms，但当前实现只封顶同步等待时长，编译产物中的时长参数仍按原值下发，存在超限攻击窗口残留的风险。影响：安全边界与宪法合规。（选项：A 拒绝整个请求——推荐；B 钳制到 60000ms 后执行；C 维持现状仅封顶等待并记录告警）
2. **[需要澄清：dry-run 模式下 stop_and_reset 是否应例外地允许连接硬件执行止损？]** 当前 dry-run 下所有工具只编译不连接硬件，意味着「紧急停止」在默认模式下无效。影响：实验安全运维与「止损不阻塞」原则的执行口径。（选项：A 维持现状——dry-run 下止损仅编译；B 允许 stop_and_reset 在 dry-run 下仍连接硬件执行；C 由操作员在启动时单独声明）
3. **[需要澄清：arp_flood 的 dst_ip（仅用于 RTT 采样关联、不下发硬件）是否必须经过 allowlist 校验？]** 当前实现不校验，但工具说明文字声称需在 allowlist 内，二者不一致。影响：安全一致性。（选项：A 必须校验——推荐，符合安全优先；B 不校验并统一修正说明文字；C 仅在 live 模式校验）
