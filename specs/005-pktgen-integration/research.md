# 研究文档：Pktgen-DPDK 硬件集成

**特性目录**: `specs/005-pktgen-integration/` | **日期**: 2026-11-19

本文档记录阶段 0 研究结论：每个决策按「决策 / 理由 / 备选方案」格式，来源为 spec.md 的待澄清问题与宪法核对中发现的技术选择。

## 澄清项采纳（Lead 指定推荐默认）

### D1（澄清 005-1）：duration > 60000ms 请求 → 拒绝（不钳制）

- **决策**: 适配器在执行/编译前拒绝 `duration > 60000` 的请求，返回参数错误；保留 `duration=0`（永久发包，由 stop_and_reset 终止）的既有语义。
- **理由**: 宪法附加约束规定「Pktgen duration≤60000ms」，硬上限应当显式拒绝而非静默改写；钳制会让「请求 120s 实际只发 60s」的观测窗口语义混乱，违背可观测驱动；拒绝迫使 Agent 收到明确参数错误并改参，闭环信息完整。校验放在适配器层而非 vendored YAML，遵守「vendored 不得私自分叉语义」。
- **备选方案**: ①钳制到 60000ms 并加告警（否决：静默改写参数、观测语义失真）；②维持现状仅封顶同步等待（否决：编译产物仍含超限时长，硬件侧实际攻击窗口超限，违反宪法上限）；③修改 vendored YAML 增加 duration 约束（否决：破坏与上游同步）。

### D2（澄清 005-2）：dry-run 下 stop_and_reset 维持现状（不连接硬件）

- **决策**: 维持现状——dry-run 下 `stop_and_reset`/`stats_monitor` 仅编译校验、不连接硬件；通过工具说明与系统提示词显式声明「dry-run 下止损只做脚本校验，不真正停止硬件」，消除 LLM 误解。
- **理由**: 「默认模式绝不触网」是单一安全不变量；为止损开例外等于给 dry-run 打开一条绕过路径，破坏安全默认的简洁性。真实实验场景中操作员已用 `--pktgen-live` 启动，止损必然可用。
- **备选方案**: ①允许 stop 在 dry-run 下例外连接硬件（否决：破坏零连接不变量）；②启动时单独声明止损权限（否决：增加 CLI 复杂度，收益小）。

### D3（澄清 005-3）：arp_flood 的 dst_ip 必须过 allowlist（安全优先）

- **决策**: `arp_flood` 提供 `dst_ip` 时，必须通过 `validate_target`（白名单 + 广播/组播检查），失败即拒绝调用；不提供 `dst_ip` 仍允许执行（ARP 本身是 L2 协议、无需 IP），仅跳过 RTT 采样。
- **理由**: 安全优先原则要求所有「影响目标选择」的输入受控；虽然 dst_ip 不下发硬件，但它决定 RTT 采样关联对象与结果解读，拒绝成本为零。实现上不并入 `_SKILLS_WITH_DST_IP`（避免把它变成必需参数），而是独立校验分支，保持「ARP 无 IP」的语义。
- **备选方案**: ①不校验、仅修正说明文字（否决：与宪法安全优先相悖）；②把 dst_ip 设为必需参数（否决：强制 IP 破坏 ARP L2 语义，且会让纯二层泛洪无法执行）。

## 宪法核对中发现的新决策

### D4（新增）：禁止 LLM 传入 src_ip（源 IP 伪造）

- **决策**: 适配器拒绝 LLM 传入 `src_ip` 参数（对 udp/tcp/icmp flood 暴露该参数者），与 Scapy 工具「src_ip must be None」口径一致；不修改 vendored YAML 中 src_ip 的默认值。默认伪造源的彻底关闭方案见 D9（Lead 定调）。
- **理由**: 宪法四明确「禁止 src_ip 伪造」，而 Pktgen 工具的 src_ip 参数允许 LLM 任意指定源地址（YAML 默认 `192.168.1.1/24` 本身即伪造源）。拒绝 LLM 自定义可阻止 Agent 主动伪造；默认伪造源是否彻底清除涉及硬件配置与上游语义，超出本特性范围，列为「仍待澄清项」上报。
- **备选方案**: ①仅允许配置源网段（否决：需新增配置面，当前无需求来源）；②维持现状（否决：直接违反宪法四）；③修改 vendored YAML 默认值（否决：私自分叉 vendored 语义）。

### D5（新增）：工具默认参数改为调用时读环境变量

- **决策**: 适配器工具签名中 `rate`/`duration` 默认值改为调用时读取 `PKTGEN_RATE`（缺省 "50"）与 `PKTGEN_DURATION_MS`（缺省 "10000"），失败回退现值；`main.py` 已设置这两个环境变量，无需改动。
- **理由**: 宪法六要求「默认值集中于 experiment.json，经环境变量注入工具并在调用时读取」；现状是 env 只参与提示词渲染，工具默认硬编码在函数签名，`--pktgen-rate`/`--pktgen-duration` 对工具默认值实际不生效。
- **备选方案**: ①维持硬编码（否决：违反宪法六且 CLI 参数失效）；②在 main.py 动态修改函数默认（否决：脆弱、不可读）。

### D6（新增）：MAC 替换明细写入结果

- **决策**: `packet_sequence` 的 eth_dst_addr 替换除 logger 记录外，在工具结果中新增 `replaced_mac` 字段（条目下标 → 替换后 MAC 列表）。
- **理由**: FR-012 要求「在日志与结果中记录替换行为」；当前仅日志记录，LLM 无法从结果判断替换发生，影响其对攻击内容的认知（可观测驱动）。
- **备选方案**: ①仅维持日志（否决：不满足 FR-012 的可测试口径）；②在 summary 中拼接（否决：结构化字段更利于测试与 LLM 解析）。

### D7（现状确认，无改动）：产物审计与错误分类

- **决策**: 维持现状——编译产物以 `lua_scripts/<时间戳>_<技能名>.lua` 保存；结果统一含 `success/skill/mode/error/summary/artifacts{lua_script,lua_preview}`；错误按「参数错误 / 连接失败→建议回落 Scapy / 其他」分类进 summary。
- **理由**: 已满足 FR-014/FR-015；lua_preview 截断 200 字符保护上下文预算。
- **备选方案**: 无（现状即契约）。

### D8（边界约束）：vendored 代码零改动

- **决策**: 本特性所有新增校验与行为变更只落在 `src/pktgen/adapter.py` 与文档/测试；不改动 `pktgen_agent/`、`dsl/skills/*.yaml`、`topology.yaml`。
- **理由**: 宪法附加约束「vendored 与上游 Lua 项目保持同步，不得私自分叉语义」。
- **备选方案**: 修改 YAML 加 duration 上限（否决，见 D1）。

## 澄清决议补录（Lead 定调，2026-11-19）

### D9（澄清·Pktgen 默认伪造源）：采纳候选 B —— experiment.json 新增合法 src_ip 配置，适配器注入

- **决策**: 采纳候选 B。在 `src/config/experiment.json` 的 `pktgen` 节新增合法源地址配置项（如 `src_ip`，默认值取授权实验环境的真实源地址），`main.py` 注入环境变量（沿用 `PKTGEN_*` 命名族），适配器在编译前把该合法源填入技能参数，覆盖 vendored YAML 的默认 `192.168.1.1/24`；LLM 自定义 src_ip 仍按 D4 拒绝。实现只落在 adapter/config/main，vendored 与 dsl 零改动。
- **理由**: 宪法四「禁止 src_ip 伪造」与宪法六「配置单一来源」同时闭环——默认伪造源被配置驱动的合法源替换，且操作员可按实验拓扑修改；比 A（自动探测出接口源）更可控、可测试，比 C（文档声明）真正满足宪法。
- **备选方案**: ①A 适配器强制注入本机出接口真实源（否决：探测逻辑脆弱、多网卡环境语义不确定、不可配置）；②C 接受现状并文档声明（否决：宪法四合规深度不足，Lead 未采纳）。
